# WT VCO 技術仕様：CV・つまみ入力部

[English](wtvco_input_spec.md) | 日本語

AE Modular 用 Wavetable VCO モジュール「WT VCO」（RP2350-Zero、**1ch**）の **CV・つまみ入力部** の設計と、その理由、検証結果をまとめる。

- **V/OCT** は RP2350 が単独で扱う。ADS1115 と RP2350 内蔵 ADC の 2 系統で読み、融合して 1 つの値にする（センサーフュージョン）。PIC は V/OCT に一切関与しない。
- **WT CV・FM CV（それぞれユニポーラ入力・バイポーラ入力の 2 系統）とつまみ**は PIC16F18426 の ADC で読み、UART で RP2350 に送る。PIC は「生値を送るだけの外付け ADC」として動作する。

対象 = RP2350 ファームウェアの入力処理（core1）と PIC ファームウェア。
音声合成（core0）は `wtvco_audio_process.ja.md` に書く。音声側は本書が定める共有変数を読んで使う（10 章）。

回路図と部品表は `../hardware/`、ファームウェアは `../firmware/` にある。本書では、設計の説明に必要な範囲で回路を抜き出して示す。

データシートの参照：ADS1115 = TI SBAS444B、PCM5102A = TI SLAS859C、PIC16F18426 = Microchip DS40001985C。

## 1. 概要

### 1.1 入力一覧

| 入力 | 種別 | 速度 | 精度 | 読み取り手段 |
|---|---|---|---|---|
| V/OCT1 | CV | 高速 | 高精度 | ADS1115 ＋ RP2350 ADC（粗） |
| WT1 CV UNI（ユニポーラ） | CV | 中速 | 低精度 | PIC ADC → UART |
| WT1 CV BI（バイポーラ） | CV | 中速 | 低精度 | PIC ADC → UART |
| FREQ1 COARSE | つまみ | 低速 | 高精度・**安定性最重視** | PIC ADC → UART（レシオメトリック） |
| FREQ1 FINE | つまみ | 低速 | 高精度 | PIC ADC → UART（レシオメトリック） |
| WT1 KNOB | つまみ | 低速 | 中精度 | PIC ADC → UART（レシオメトリック） |
| FM1 CV UNI（ユニポーラ） | CV | 中速（低速の変調専用） | 低精度 | PIC ADC → UART |
| FM1 CV BI（バイポーラ） | CV | 中速（低速の変調専用） | 低精度 | PIC ADC → UART |
| FM1 DEPTH | つまみ | 低速 | 低精度 | PIC ADC → UART（レシオメトリック） |

### 1.2 出力構成（参考。処理は音声側）

| 出力 | 内容 |
|---|---|
| OUT1 | オシレーター出力。PCM5102A の OUTL（GND 中心 ±1.5V）を出力バッファで **1〜4V（2.5V 中心）** にして出す（`wtvco_audio_process.ja.md` §1.3） |

### 1.3 音程の決め方（参考。計算は音声側）

周波数は次で決まる。

```
f = f_C0 × 2^((coarse_cent + fine_cent + voct_cent + fm_cent) / 1200)
```

| 要素 | 範囲 | 決め方 |
|---|---|---|
| `f_C0` | 定数 | C0 の周波数 |
| `coarse_cent` | 0〜7200 cent | FREQ COARSE。C0〜C6 の 72 半音ぶんの幅を連続的に動く |
| `fine_cent` | −100〜+100 cent | FREQ FINE。COARSE で粗く合わせた音程を直す（中央で 0） |
| `voct_cent` | 0〜6000 cent | V/OCT 入力。0〜5V（0〜6000 にクランプ。未接続時は 0 にならず、約 0.2〜0.3V ぶん高くなる。6 章） |
| `fm_cent` | −6000〜+18000 cent | FM（指数 FM ＝ ピッチ変調）。FM CV（−2.5〜+7.5V）× FM DEPTH（0〜2400cent/V）。未接続時 0（2.5、8.6） |

- 音名は A4 = 440Hz の科学的音名表記とする（C0 ≒ 16.35Hz、C3 ≒ 130.81Hz、C6 ≒ 1046.5Hz）。
- COARSE は PIC の ADC（12bit）で 7200cent を表すので、**ADC の 1LSB ≒ 1.76cent**。1LSB のふらつきがそのまま音程の揺れとして聞こえるため、
  COARSE は安定性を最優先に処理する（7.2、8.3）。平均した値を 14bit で送る（7.3）ので、RP2350 には 0.44cent 刻みで届く。
- FM なしの最高音は COARSE・FINE・V/OCT がすべて最大のとき 13300cent = C11 ＋ 100cent（約 35.5kHz）になる。
  FM を含めると取りうる範囲は −6100〜+31300cent まで広がるが、音声側で C0〜C11 直下にクランプされる。
  上限・下限の扱い（クランプ、エイリアス対策）は音声側で決める。

### 1.4 V/OCT で解きたい問題

- V/OCT は AE Modular 仕様で 0〜5V、出力インピーダンス約 1kΩ。1V/oct なので 0〜5V = 0〜6000cent。
- **精度要求**: 定常時 1LSB <= 3cent（= 2.5mV）。
- **速度要求**: ノートオン時の追従 <= 500µs（音声出力まで含めて）。

ADS1115 は精度要求を満たすが（±6.144V レンジで 1LSB = 187.5µV ≒ 0.22cent、入力インピーダンスは
同相 10MΩ・差動 22MΩ（データシート Table 2 ほか）、バッファ・分圧なしで直結可）、
最大 860SPS = 1 変換あたり公称 1.163ms（内部発振器のばらつき ±10% で 1.057〜1.292ms）で、速度要求を満たさない。

RP2350 内蔵 ADC（12bit、500kSPS、ENOB 約 9.2）は速度要求を満たすが、精度は足りない。

### 1.5 V/OCT の解法

両方を同時に読み、**定常時は ADS1115、変化中は内蔵 ADC（粗）** を採用する。

- ノートオン直後の約 1.1〜2.7ms（5.5）だけ粗精度（数 cent〜十数 cent の誤差）になる。これは許容する。
- 1200cent 級のずれ（前のノートの値が残ることによる「キュッポン」音）は**許容しない**。これが本機構の存在理由。

### 1.6 用語

| 用語 | 意味 |
|---|---|
| ノード | V/OCT ジャック直後の 1kΩ の後ろ、ADS1115 入力・バッファ入力・プルダウンが集まる点 |
| 粗 ADC / 粗値 | RP2350 内蔵 ADC で読んだ V/OCT（バッファ＋分圧経由） |
| 生サンプル | 粗 ADC の 1 変換の値。**2µs ごと**（500kSPS、3.1） |
| 粗サンプル `p` | 生サンプルを 16 個ずつ区切って平均した値（**32µs ごと**、3.2）。ウィンドウの統計に使う |
| 移動平均値 `s` | 直近 16 個の生サンプルの移動平均（**生サンプルごと = 2µs ごと**に更新、3.2）。急変判定と FAST モードの出力に使う |
| クリーンな変換 | ADS1115 の変換ウィンドウ中に入力がほぼ動いていなかった変換 |
| ADS モード | V/OCT の出力に ADS1115 の値を使っている状態 |
| FAST モード | V/OCT の出力に粗値を使っている状態 |
| 変換ウィンドウ | ADS1115 のある 1 変換の開始〜完了の区間（RDY の立ち下がり間隔） |
| フレーム | PIC が UART で送る、全 8ch の値をまとめた 1 単位（7 章） |
| ユニポーラ入力（UNI） | CV 入力（WT CV・FM CV）のひとつ。0〜5V を 0V 基準の上向きの変調（0〜+5V）として解釈する。未接続時 0V（2.5） |
| バイポーラ入力（BI） | CV 入力（WT CV・FM CV）のひとつ。**受ける電圧は 0〜5V**で、これを 2.5V 中心の ±2.5V の変調として解釈する。±の電圧を受ける入力ではない。未接続時 2.5V（2.5） |
| 送信値 `raw` | PIC が送る各入力の値。ADC（12bit）の平均値 × 4 の **14bit（0〜16380）**（7.2、7.3）。RP2350 側の換算はすべてこの値で行う |
| ゼロ点 | CV 入力ごとの「変調 0」とみなす送信値。未接続時の生値を測って保存する（9.4） |

## 2. ハードウェア構成

### 2.1 電源

```
AE 5V バス ──┬──────────────── ADS1115 VDD / V/OCT バッファ（MCP6001）V+ / I2C プルアップ
             │
             ├──────────────── PIC16F18426 VDD（＝つまみ上端、2.5）
             │
             ├──────────────── 出力バッファ（MCP6001）V+（`wtvco_audio_process.ja.md` §1.3）
             │
             ├──────────────── XC6206（3.3V LDO）── PCM5102A
             │
             └──|>|── RP2350-Zero 5V ピン    （ショットキーダイオード）
```

- **動作は AE バス給電が前提。** ADS1115・V/OCT バッファ・PIC・PCM5102A・出力バッファはすべて AE バスから給電されるので、
  **USB 単独給電は動作対象外**とする（RP2350 以外は何も動かないので、縮退動作なども用意しない）。
- **USB は、AE バス給電中にモニター・校正コマンド（9 章）・書き込みのために併用する。**
- **ショットキーダイオード**: その併用時に PC の VBUS と AE の 5V バスがぶつからないようにする。
  **RP2350-Zero の 5V ピン（ヘッダ 23 番、回路図のネット名 VBUS）は USB-C の VBUS に直結で、ダイオードはない**
  （Waveshare 公開の回路図による。VBUS にあるのは ESD 保護の ESD5451N だけ）。**外付けのショットキーダイオードは必須。**
  3.3V は VBUS から LDO（ME6217C33M5G、CE は VIN に直結）で作る。0.3V 程度の降下は問題ない。
- USB を挿したまま AE バスの電源を切ると、RP2350 だけが動き続け、電源の落ちた PCM5102A に I2S を出し続ける。
  PCM5102A のデジタル入力（BCK・LRCK・DIN）はフェイルセーフ入力（Failsafe LVCMOS。データシート 7 章 ピン機能表の注 1）なので壊れはしないが、
  この状態で長時間放置しない。（絶対最大定格の 3.9V（データシート 8.1）は DVDD = 3.3V のときの値で、電源断時の根拠にはならない。）

### 2.2 V/OCT 入力回路

```
                                            +-----------+
V/OCT IN --[ 1kΩ ]--+----------------------| ADS1115   |
  (jack)            |                       | AIN1      |
                    |                       +-----------+
                    +--[ 10MΩ ]-- GND
                    |
                    +--[ 1nF ]-- GND
                    |
                    |   +------------------+
                    +---| MCP6001          |--[ 10kΩ ]--+-- ADC1 (RP2350 GP27)
                        | ボルテージフォロワ |            |
                        +------------------+          [ 15kΩ ]
                                                        |
                                                       GND
```

- **1kΩ（ジャック直後）**: 短絡保護と入力電流制限。
- **1nF**: ADS1115 入力の安定化。1kΩ との時定数は 1µs で、ADS1115 の変換ウィンドウ（約 1.16ms）・粗 ADC の生サンプル（2µs）に対して十分短い。
- **10MΩ**: プルダウン。未接続時にノードを GND 側へ引く。**0V までは落ちない**（ADS1115 の入力が約 0.7V 側へ引くため、約 0.2〜0.3V に落ち着く。6 章）。
  値を下げると、相手の出力インピーダンス（約 1kΩ）＋保護の 1kΩ との分圧で V/OCT の誤差が増え、しかも相手のモジュールごとに変わるので校正しきれない。
  10MΩ なら GND への引き込みは約 0.02%（5V で約 1.2cent）、相手のインピーダンスが 1kΩ 変わっても約 0.6cent で、校正で吸収できる範囲に収まる。
- **MCP6001**（5V 単電源 RRIO、1 回路）: ノードと粗 ADC 側を切り離すバッファ。V+ = 5V、V- = GND、電源ピン直近に 0.1µF。
  - 出力バッファ（`wtvco_audio_process.ja.md` §1.3）も MCP6001 で、このバッファとは別の IC にする。
  - MCP6002（2 回路）を使う場合は、残りの 1 回路をボルテージフォロワにして非反転入力を GND に落とす。
  - ノードに直接分圧をぶら下げると、相手モジュールの出力インピーダンスのばらつきが ADS1115 側の絶対誤差になるため、**分圧は必ずバッファの後ろ**に置く。
  - **ゼロドリフト（チョッパ）型オペアンプは使用禁止**（入力にパルス電流を出し、ノードを汚すため）。
- **分圧 10kΩ / 15kΩ**: 比 0.6。5V 入力で 3.0V になり、ADC 上限（IOVDD = 3.3V）に余裕を残す。
  上側 10kΩ はフォロワの容量性負荷対策を兼ねる。テブナン抵抗 6kΩ で、ADC のサンプリングには十分低い。
  ADC ピン側にコンデンサは置かない。
- **RP2350 の ADC ピンは 5V トレラントではない**。入力上限は IOVDD（3.3V）で決まる。

### 2.3 ADS1115 の構成

| 項目 | 値 |
|---|---|
| 担当 | V/OCT1 |
| I2C バス | I2C0（GP8 = SDA、GP9 = SCL） |
| ADDR ピン | GND（アドレス 0x48、データシート Table 5） |
| 入力 | AIN1 固定（5 番ピン。基板の配線に合わせた） |
| 動作 | 連続変換、ALERT/RDY を変換完了通知に使用（RDY = GP10） |
| 電源 | **5V 駆動** |

- 1 バス 1 デバイス。
- **5V 駆動**にするのは、V/OCT（0〜5V）を分圧なしで受けるため。アナログ入力は VDD + 0.3V を超えられない（データシート 絶対最大定格・注記）。
  ±6.144V レンジでも実際に測れるのは 0〜VDD の範囲で、0〜5V の V/OCT はこれに収まる。
- AIN0・AIN2・AIN3 は未使用（GND に接続）。未使用入力を過大入力にしないこと（データシート「MULTIPLEXER」：未使用入力の過大入力は他の入力の変換に影響しうる）。

### 2.4 I2C・RDY のプルアップ

- SDA/SCL は **5V へ 4.7kΩ でプルアップ**する。
  - RP2350 の GPIO（FT パッド、データシート 14.8.2.1）は、**IOVDD が入っている（2.5V 以上）間は 5.5V まで**入力に耐える。
    **IOVDD = 0V のときは 3.63V まで**しか許されない。
  - I2C はオープンドレインで、RP2350 は High を出力しない。ピンが 5V を出すことはない。
  - ADS1115（5V 駆動）の VIH = 0.7 × VDD = 3.5V（データシート 電気的特性）と、RP2350 の VIH = 2.0V の両方を満たす。**レベル変換 IC は不要。**
  - **電源投入時も条件を外れない。** RP2350 の 3.3V は同じ AE 5V バスから（ショットキーダイオード＋RP2350-Zero の LDO 経由で）作られ、
    バスと一緒に立ち上がる。バスが 3.63V を超える時点で IOVDD はすでに 3V 前後あり、2.5V 以上の条件を満たす。
    - FT パッドはほとんど電流を流さないので、**直列・プルアップ抵抗で電流を制限しても、ピン電圧は下がらない**。
      安全性の根拠は電流制限ではなく、上記の「一緒に立ち上がる」ことにある。
    - 電源の投入時と断のときに、5V バスと RP2350-Zero の 3V3 ピンをオシロで同時に観測し、条件を満たすことを確認した（13.3）。
  - この議論は、5V にプルアップされる／5V を受ける全ピン（I2C、RDY、UART RX）に共通する。
- ALERT/RDY はオープンドレイン出力。**3.3V へ 10kΩ でプルアップ**する（5V でも可）。
- クロックは 400kHz（ADS1115 の Fast mode 上限。データシート Table 1）。ADS1115 はクロックストレッチをしない。

### 2.5 PIC 周りの回路

#### つまみ（4 個）

```
PIC VDD ──+──────────────+──────────────+──────────────+
          |              |              |              |
        [10kB]         [10kB]         [10kB]         [10kB]
          |              |              |              |
    FREQ1 COARSE     FREQ1 FINE      WT1 KNOB       FM1 DEPTH     → PIC アナログ入力（各ワイパーに 100nF）
          |              |              |              |
GND ──────+──────────────+──────────────+──────────────+
```

- つまみの上端は **PIC の VDD ピンと同じノード**から取り、ADC の基準は VREF+ = VDD とする。
  これで**レシオメトリック**になり、5V バスの変動は読み値に乗らない。
- ワイパーの 100nF は、ADC のサンプリング容量への電荷供給とノイズ除去を兼ねる。
  **FREQ1 COARSE は 1µF に増やしてもよい**（ノイズをさらに落とす。応答は遅くなるが低速用途なので問題ない）。
- FREQ1 COARSE には、ガリの出にくい品質の良い可変抵抗を使う（1LSB ≒ 1.76cent のため、摺動ノイズがそのまま音程に出る）。
- PIC の電源ピン直近に 0.1µF ＋ 0.01µF（データシート 39.4.2 の注記：HFINTOSC の精度保証条件）＋ 10µF。

#### WT CV（ユニポーラ入力・バイポーラ入力）

AE Modular の CV は 0〜5V のユニポーラなので、1 つの入力では WT を上向きにしか変調できない。
そこで WT CV の入力（AE ではピンソケット）を 2 つ設ける。

| 入力 | 受ける電圧 | 解釈（変調量） | 未接続時 |
|---|---|---|---|
| WT1 CV UNI（ユニポーラ） | 0〜5V | 0V 基準。0〜+1.0（上向きだけ） | プルダウンで 0V → 変調 0 |
| WT1 CV BI（バイポーラ） | 0〜5V | 2.5V 中心。−0.5〜+0.5（上下両方） | バイアスで 2.5V → 変調 0 |

- **感度は両入力で同じ**（1V = WT 0.2）。
- **両挿しを認める。** 内部で合算する（8.4）。例：ADSR を UNI、LFO を BI に挿すと、ADSR＋LFO の複合変調になる。
- 切り替えスイッチではなく入力を 2 つにするのは、PIC の ADC ピンに余裕があり、ピンソケットの追加のほうがスイッチより狭く安く済むため。
- **挿す先で結果が変わる。** ADSR など 0V 基準の CV を BI に挿すと、休止中（0V）に WT が −0.5 ずれる。
  LFO を UNI に挿すと上向きにしか振れない。パネルの表記で UNI / BI を区別できるようにする。

```
WT UNI IN --[ 1kΩ ]--+-- PIC アナログ入力（RC3）
 (pin)               |
                     +--[ 100kΩ ]-- GND
                     |
                     +--[ 100nF ]-- GND      ← PIC のピン直近
```

```
                          PIC VDD（つまみ上端と同じノード）
                             |
                          [ 200kΩ ]
                             |
WT BI IN --[ 1kΩ ]--+--------+-- PIC アナログ入力（RC4）
 (pin)              |
                    +--[ 200kΩ ]-- GND
                    |
                    +--[ 100nF ]-- GND       ← PIC のピン直近
```

- PIC は 5V 駆動なので**分圧は不要**。1kΩ は保護用。
- **UNI の 100kΩ** は未接続時に 0V へ落とすためのプルダウン。
- **BI の 200kΩ × 2** は PIC の VDD を 2 等分するバイアス（テブナン等価で 2.5V / 100kΩ）。
  - ADC の基準（VREF+ = VDD）と同じ電源から作るのでレシオメトリックになり、未接続時は 5V バスが変動しても常に ADC の中点（12bit で約 2048、送信値で約 8190）を読む。
    これは理論換算（8.4）の 2.5V と一致するので、**未接続時の変調はバス電圧によらず 0** になる。
  - 2 本は 1% 品の同じ値を使う。抵抗のずれ（最大 約 25mV）はゼロ点校正（9.4）で打ち消すが、校正前の初期状態でもずれを小さくしておくため。
- **入力の負荷による誤差**：相手の出力インピーダンス（約 1kΩ）＋保護の 1kΩ と、テブナン抵抗 100kΩ との分圧で約 2% のゲイン誤差が出る。
  UNI は 0V を中心に、BI は 2.5V を中心にスケールが縮むので、**BI の中点（変調 0）はずれない**。RP2350 側の校正（9.4、任意）で吸収する。
- **100nF（PIC のピン直近）**：ADC のサンプリング容量への電荷供給と、ノイズ・エイリアス除去を兼ねる。
  - データシートはアナログ源のインピーダンスを **10kΩ 以下**に推奨している（DS40001985C 32.3、図 32-4、式 32-1 の注 3）。
    WT CV の入力側は未接続時 100kΩ、接続時も約 2kΩ＋α あるので、サンプリング時の電荷はピン直近のコンデンサから供給する。
  - **電荷分配の誤差**：サンプル＆ホールド容量 CHOLD = 28pF（図 32-4）は変換ごとに放電されない（式 32-1 の注 2）ので、
    ch を切り替えた直後の取得では、直前の ch の電圧が残った CHOLD とコンデンサの間で電荷が分配される。
    最悪（5V の差）でも 5V × 28pF / 100nF ≈ **1.4mV（約 1.1LSB）**。バースト平均の 2 回目以降は無視できる。低精度用途なので問題ない。
  - **リーク電流の誤差**：10kΩ の推奨はピンのリーク電流の仕様を満たすためでもある（式 32-1 の注 3）。
    DC のリークはコンデンサでは補えないので計算しておく。I/O ポートの入力リーク IIL は典型 ±5nA・最大 ±125nA（39 章 D340）。
    未接続時（100kΩ）で最悪 12.5mV（WT 0.0025）、典型 0.5mV。接続時（約 2kΩ）は最悪 0.25mV。**無視できる。**
  - **帯域**：接続時の時定数は約 2kΩ × 100nF = 200µs（fc ≈ 0.8kHz）。PIC のサンプリング（1 フレーム 1ms）に対するアンチエイリアスを兼ねる。
    未接続時は 100kΩ × 100nF = 10ms になるが、入力は静止しているので問題ない。
  - コンデンサはリークの小さいセラミックを使う（データシート 34.9：アナログ入力に付ける部品はリークが小さいこと）。
    PIC のピンに最短で付け、GND は PIC の VSS へ短く戻す。
- WT CV は他モジュールが出す絶対電圧なので、VDD（5V バス）の変動ぶんの誤差は受ける。低精度用途なので許容する。
- 未接続時のずれ（BI のバイアス抵抗の誤差、PIC の ADC のオフセット、ピンのリーク電流）は、**ゼロ点校正（9.4）**で打ち消す。

#### FM CV（ユニポーラ入力・バイポーラ入力）と FM DEPTH

周波数変調（**指数 FM ＝ ピッチ変調**）用の入力。

- **LFO・エンベロープなどによる低速の変調専用**とする。CV は PIC 経由で 1ms ごとに読み、入力の RC も fc ≈ 0.8kHz なので、
  オーディオレート FM（FM 音源のような倍音を作る変調）は対象外。
- **入力の構成・回路・未接続時の扱いは WT CV と同じ。** 上記の UNI・BI の回路（1kΩ、100kΩ プルダウン／200kΩ × 2 バイアス、ピン直近の 100nF）をもう 1 組設ける。
  UNI = RC5、BI = RA4（2.7）。
- 感度は両入力で同じ。合算した電圧 `fm_v`（−2.5〜+7.5V）に、FM DEPTH で決めた感度を掛けて音程の変化量にする（8.6）。
- **FM DEPTH つまみ**で、1V あたりの音程の変化量を **0〜2400cent/V** の範囲で決める。カーブは非直線（2 乗。8.3）。
- 変調の範囲は DEPTH 最大で **−6000〜+18000cent（−5〜+15oct）**。音程は音声側で C0〜C11 直下にクランプされる。
- **CV の誤差は DEPTH 倍で音程に出る。** 1LSB（1.22mV）は DEPTH 最大で約 2.9cent。
  未接続時のずれ（例：BI のバイアス抵抗の誤差 最大 約 25mV は DEPTH 最大で約 60cent）は**ゼロ点校正（9.4）で打ち消す**。FM CV では実質必須。
- 精度は**低精度として許容**する。DEPTH を 1200cent/V に合わせても、V/OCT のような正確な 1V/oct の追従は求めない。

#### UART（PIC → RP2350、片方向）

```
PIC TX (RA5) --[ 4.7kΩ ]-- RP2350 GP1 (UART0 RX)
```

- PIC の TX は 5V だが、RP2350 の GPIO は 5V トレラントなので直結できる（条件は 2.4 と同じ）。
  PIC の TX が High を出し始めるのは PIC のファームが UART を初期化した後なので、その時点で RP2350 の 3.3V は確実に立ち上がっている。
- **4.7kΩ の直列抵抗は保護用に入れる**（GP1 を誤って出力に設定したときなどの短絡電流の制限）。
  FT パッドの 5V 耐圧の条件を満たすためのものではない（2.4）。
  （RP2350 側のピン容量と合わせても時定数は 100ns 以下で、1Mbps の 1bit = 1µs に対して十分短い。）
- **GP1 は内部プルアップを有効にする**（ファーム）。PIC を載せていないとき（8.2）は GP1 の先に何もつながらず、
  既定の内部プルダウンのままだと RX が Low に引かれてフレーミングエラーが出続ける。
  PIC を載せていれば PIC の TX が High を出すので影響はない。外付けのプルアップは不要。
- RP2350 → PIC の信号線はない。

#### 書き込みと MCLR

- **PIC は基板の外（ブレッドボードなど）で書き込んでから、基板のソケットに実装する**（手順は `../firmware/README.md`）。
  基板上に ICSP ヘッダは設けない。
  - RA0（ICSPDAT）・RA1（ICSPCLK）には外部の信号をつないでいない（2.7）。後から ICSP ヘッダを足す余地は残る。
  - 基板側の PIC は **DIP ソケットに載せる**（書き換えのたびに抜き差しするため）。
- **RA3（MCLR）は 10kΩ で VDD へプルアップ**する。コンフィグは MCLRE = 1（MCLR 有効）とする。

## 3. RP2350 内蔵 ADC（V/OCT 粗読み）

### 3.1 設定

| 項目 | 設定 | 備考 |
|---|---|---|
| クロック | 48MHz、CLKDIV = 0 | 最速 500kSPS（1 変換 96 サイクル = 2µs） |
| チャンネル | AINSEL = 1（ADC1 = GP27）固定、**ラウンドロビンなし**（RROBIN = 0） | V/OCT1 だけを 500kSPS で読む |
| FIFO | 有効、DREQ 有効、SHIFT = 0（12bit のまま） | |
| 転送 | DMA でリングバッファへ（16bit × 1024 以上、2 のべき乗）。**書き込み側をリングラップ**、**止まらずに回り続ける** | CPU を使わずに常時サンプリング。1024 個で約 2ms ぶん |

- **サンプリングは常時一定の周期で回し続ける**。状態によって止めたり、レートを変えたりしない。
- DMA リングの書き込み位置が、そのまま時間軸（**2µs / サンプル**）になる。
- **リングバッファは、リング長と同じバイト境界に配置する**（16bit × 1024 = 2048 byte なら 2048 byte 境界）。DMA のリングラップはアドレスの下位ビットを
  折り返すだけなので、境界がずれているとバッファの外へ書き込む。
- **無限に回す方法は音声側の出力リングと同じ**で、RP2350 の DMA の ENDLESS モードを使う（arduino-pico 6.1.0 同梱の pico-sdk の
  `dma_encode_endless_transfer_count()`。`wtvco_audio_process.ja.md` §1.11）。

### 3.2 前処理

core1 は DMA リングを追いかけ、2 種類の平均を作る。

| 値 | 作り方 | 更新 | 用途 |
|---|---|---|---|
| 粗サンプル `p` | 生サンプル 16 個ずつ区切って平均 | **32µs ごと**（31.25kHz） | 変換ウィンドウの統計（静止判定・`ref`） |
| 移動平均値 `s` | 直近 16 個の生サンプルの移動平均 | **生サンプルごと（2µs ごと）** | **急変判定と FAST モードの出力**（5 章） |

- `s` は「合計に新しいサンプルを足し、16 個前のサンプルを引く」で求める。16 個前のサンプルは DMA リングにそのまま残っているので、追加のバッファは要らない。
- 窓の長さが同じなので、`s` と `p` のノイズの大きさは同じ。`s` は急変を `p` の区切り（32µs）を待たずに検出するためのもの。
- core1 はループ 1 周ごとに、前回から DMA が書き足した生サンプルをまとめて処理する（1 周 10µs 以内なので 1 回あたり 5 サンプル前後。10.1）。
- FIFO の ERR ビット（変換エラー）が立った生サンプルは、移動平均の窓を崩さないよう**直前の値で置き換える**。
- **core1 の処理が遅れて DMA にリング 1 周以上追い越されると、書き込み位置の差だけでは遅れを検出できない**（差がリング長で折り返すため）。
  検出できないままだと、ウィンドウを閉じる位置が毎回約 1 周ずれ、ADS1115 の結果とウィンドウの対応が取れなくなる。
  そこで、前回の処理からの経過時間が 1.92 ms（リング 1 周 = 2.048 ms より短い値）を超えたときもあふれとみなし、
  移動平均とウィンドウ境界の待ち行列（4.3）を作り直す。

粗サンプル 1LSB（12bit 生値）の入力換算:
3.3V / 4096 / 0.6 ≒ 1.34mV ≒ **1.6cent**。16 サンプル平均で、ランダムノイズは約 1/4 になる。

## 4. ADS1115 の設定

### 4.1 レジスタ設定

| 項目 | 設定 | 理由（データシート） |
|---|---|---|
| MUX | AIN1 シングルエンド固定（MUX[2:0] = 101：AINP = AIN1、AINN = GND） | MUX を切り替えないので連続変換が使える |
| PGA | FSR ±6.144V（PGA[2:0] = 000） | 0〜5V を分圧なしで受けるため必須。1LSB = 187.5µV ≒ 0.22cent |
| MODE | 連続変換（0） | |
| DR | 860SPS（111） | 変換周期 公称 1.163ms。内部発振器のため **±10%**（データシート「Data rate variation」）→ 1.057〜1.292ms |
| COMP_POL | 0（アクティブ Low） | RDY を立ち下がりで検出する |
| COMP_QUE | 11 以外（例: 00） | 11 だとコンパレータ＝RDY 出力が無効になる |
| Hi_thresh | 0x8000（MSB = 1） | **RDY 機能を有効にするための必須設定**（データシート「CONVERSION READY PIN」） |
| Lo_thresh | 0x0000（MSB = 0） | **同上。忘れると割り込みが一切来ない** |

- Config レジスタの値は、COMP_QUE = 00 のとき **0x50E0**（OS = 0、MUX = 101、PGA = 000、MODE = 0、DR = 111、COMP_MODE/POL/LAT = 0、COMP_QUE = 00）。
- 設定を書いた後、**ポインタレジスタを Conversion（0x00）に戻しておく**。
  以後の読み出しはアドレス＋2 バイトの読みだけで済む（400kHz で約 70µs、4.4）。この間 core1 を止めないよう、読み出しはノンブロッキングで行う（4.4）。
- 連続変換中は、ALERT/RDY に**変換ごとに約 8µs の Low パルス**が出る（データシート「CONVERSION READY PIN」）。この立ち下がりを使う。
- **変換周期を時間で決め打ちしないこと**。±10% のばらつきがあるため、必ず RDY を基準にする。

### 4.2 変換ウィンドウの定義

- RDY(n) の立ち下がり 〜 RDY(n+1) の立ち下がり = 変換 n+1 のウィンドウ。
- ADS1115 はこの区間の入力を平均した値を返す（ΔΣ＋sinc フィルタ。周波数特性はデータレートの整数倍に零点を持つ。データシート 図 21）。
- したがって「この区間で粗値が動いていなかったか」を見れば、その変換結果が信用できるか判定できる。

### 4.3 RDY とサンプル列の対応付け

- RDY の GPIO 割り込みハンドラでは、**その時点の DMA 書き込み位置を記録するだけ**にする。
  I2C の読み出しはハンドラの外（core1 のループ）で行う。**割り込みは core1 で登録する**（core0 は音声専用。10.1）。
- 記録した位置がウィンドウの境界になる。ウィンドウの統計は、この境界で区切った粗サンプルから計算する。
  読み出しが多少遅れても、境界の時刻は正確に保たれる。
- 割り込み遅延（数 µs）は、粗サンプル 1 個分（32µs）より十分小さいので無視してよい。
- 実装では、RDY 割り込みが「DMA の書き込み位置」と「RDY の通し番号」の組を待ち行列に積み、粗 ADC の処理がその位置に達したらウィンドウを閉じる。
  ADS1115 の読み出し結果にも同じ RDY 番号を付け、閉じたウィンドウと番号で照合する。結果とウィンドウの取り違えを防ぐため。

### 4.4 ノンブロッキング読み出し

arduino-pico の `Wire` は読み出しが終わるまで戻らない。その間は急変判定が止まり、V/OCT のレイテンシが延びる。
そこで **`Wire` は使わず、pico-sdk の `hardware_i2c`（DW_apb_i2c のレジスタ）を直接使い、I2C の FIFO を利用して待たずに読む。**

読み出し 1 回のバス時間（400kHz、データシート 図 30 の「Read Word」で Pointer 書き込みを省略した形）：

```
START ＋ アドレス 9 クロック ＋ データ 9 クロック × 2 ＋ STOP ≈ 28 SCL ≈ 70µs
```

1. 初期化時に、ターゲットアドレス（`IC_TAR` = 0x48）を設定し、ADS1115 のポインタを Conversion に戻しておく（4.1）。
2. ウィンドウ境界に達したら、`IC_DATA_CMD` に**読み出しコマンドを 2 個**書く（2 個目に STOP を付ける）。TX FIFO に入るだけなので即座に戻る。
3. 以後のループで `IC_RXFLR` を見て、**2 バイト揃っていたら取り出す**（約 70µs 後）。揃っていなければ何もせず次へ進む。
4. NACK などの中断は `IC_RAW_INTR_STAT` の TX_ABRT で検出し、その変換は捨てる（`IC_CLR_TX_ABRT` で解除。11.2）。
5. 読み出し中も、生サンプルの処理（移動平均・急変判定・出力）は止めない。閉じたウィンドウの統計は保存しておき、結果が来た時点で判定する（5.3）。

- 次の RDY までに結果が来なければ、その変換は捨てる（11.2）。
- 読み出しコマンドは最大 2 組まで積み、受信は**必ず 2 バイトの組で**取り出す（新しい組が控えていれば古い組は捨てる）。
  受信 FIFO を途中で空にしてはいけない。バイトの組がずれて、例えば 3.00 V が −5.60 V と読めてしまう。

## 5. センサーフュージョン アルゴリズム（V/OCT）

### 5.1 原理

判定は必ず**粗値どうしの比較**で行う。ADS1115 値と粗値を直接比較すると、
両者の校正誤差（オフセット・ゲイン）が閾値に乗ってしまい、閾値を大きく取らざるを得なくなる。

### 5.2 状態と変数

| 変数 | 意味 |
|---|---|
| `state` | `ADS` または `FAST` |
| `p` | 粗サンプル（32µs ごとに更新）。ウィンドウ統計用 |
| `s` | 移動平均値（生サンプルごと = 2µs ごとに更新）。急変判定と FAST モードの出力用 |
| `ref` | 直前のクリーンな変換ウィンドウにおける `p` の平均。急変判定の基準 |
| `offset` | `to_coarse_scale(ads_val) - ref`。FAST モード時の補正値 |
| `ads_val` | 直近のクリーンな ADS1115 値 |
| `win_min` / `win_max` / `win_sum` / `win_cnt` | 現在の変換ウィンドウ中の `p` の統計。RDY ごとにリセット |
| `window_discarded` | このウィンドウを破棄するフラグ（粗 ADC の FIFO ERR・DMA のオーバーランなど。11.2） |
| `closed` | 閉じたウィンドウの統計（`min` / `max` / `sum` / `cnt` / `discarded`）の控え。I2C の結果待ちの間保持する |
| `i2c_pending` | I2C 読み出しの結果待ち中フラグ（4.4） |
| `jump_cnt` | 急変判定の連続回数（**生サンプル単位**） |
| `dirty_cnt` | ADS モード中に、クリーンでないウィンドウが連続した回数（**ウィンドウ単位**）。取り残し防止用（5.3、5.5） |

### 5.3 擬似コード

```c
// --- 生サンプルごと（2µs。core1 ループで DMA の新着分をまとめて処理） ---
s = moving_average_16(raw);                // 3.2

if (state == ADS) {
    if (abs(s - ref) > T_JUMP) {
        if (++jump_cnt >= JUMP_CONFIRM) {  // 17 生サンプル = 34µs。単発スパイク除け（5.4）
            state = FAST;
            jump_cnt = 0;
        }
    } else {
        jump_cnt = 0;
    }
}

// --- 粗サンプルごと（16 生サンプル = 32µs） ---
win_min = min(win_min, p);
win_max = max(win_max, p);
win_sum += p;
win_cnt++;

// --- 出力（core1 ループ 1 周ごと。10µs 以内） ---
out_raw = (state == ADS) ? ads_val : to_ads_scale(s + offset);
out = smooth(out_raw);                     // 5.5 参照
voct_cent = clamp(to_cent(out), 0, 6000);  // 共有変数へ（10.2）。範囲外はクランプ（6 章）

// --- ウィンドウ境界（RDY で記録した位置に生サンプル列が到達したとき） ---
closed = { win_min, win_max, win_sum, win_cnt, window_discarded };
i2c_start_read();                          // 4.4。コマンドを FIFO に積むだけで即座に戻る
i2c_pending = true;
win_min = +INF;  win_max = -INF;  win_sum = 0;  win_cnt = 0;   // 前のウィンドウの p を持ち込まない
window_discarded = false;

// 取り残し防止（下記）。I2C の結果を待たずに、粗値の統計だけで判定する
if (state == ADS && !closed.discarded && closed.cnt > 0) {
    if ((closed.max - closed.min) >= T_STILL) {
        if (++dirty_cnt >= DIRTY_CONFIRM) {    // ゆっくり動き続けている入力
            state = FAST;                      // スムージング付きで移る（5.5）
            dirty_cnt = 0;
        }
    } else {
        dirty_cnt = 0;
    }
}

// --- I2C の結果が揃ったとき（4.4。境界から約 70µs 後） ---
ads_result = i2c_take_result();
i2c_pending = false;
cand_ref = closed.sum / closed.cnt;
if (!closed.discarded
    && closed.cnt > 0
    && (closed.max - closed.min) < T_STILL
    && abs(s - cand_ref) <= T_JUMP) {      // 結果待ちの間に入力が動いていないこと（下記）
    ads_val = ads_result;
    ref     = cand_ref;
    offset  = to_coarse_scale(ads_result) - ref;
    state   = ADS;                         // 復帰はスムージング付き
    dirty_cnt = 0;
    calib_collect_pair(ads_result, ref);   // 9.3 自動相対校正用
}
```

- 1 ウィンドウあたりの粗サンプル数は約 36 個（1.163ms / 32µs。データレートのばらつきで 33〜40 個）。
- **結果待ちの間の急変に注意。** ウィンドウが閉じてから I2C の結果が来るまでの約 70µs の間にノートが変わると、
  結果（前のノートの値）で ADS モードに戻してしまう。これを防ぐため、結果を採用する時点で
  `s` が閉じたウィンドウの平均から `T_JUMP` 以上離れていないことを確認する。離れていれば結果は捨てる
  （急変判定は並行して進んでいるので、FAST モードへの遷移はそのまま起きる）。
- **ADS モードでの取り残しを防ぐ。** ウィンドウがクリーンでない（幅が `T_STILL` 以上）のに `s` が `ref` から `T_JUMP` 以内、という状態では、
  急変判定も ADS1115 値の更新も働かず、出力が古い `ads_val` のまま止まる。
  - 例 1：ゆっくりしたグライドの出だし。`T_STILL` = 5cent なら約 4cent/ms 以上（1 オクターブを約 0.3 秒以下）の動きで、
    ずれが `T_JUMP` に達するまで出力が止まる。
  - 例 2：振幅が `T_JUMP` 未満の速い揺れやハム。出力が止まったままになる。
  - そこで、**ADS モード中にクリーンでないウィンドウが `DIRTY_CONFIRM` 回続いたら FAST モードへ移る。**
    FAST モードでは粗値で追従し、入力が止まれば次のクリーンな変換で ADS モードに戻る。
  - 破棄されたウィンドウ（`discarded`）は数えない（連続回数もリセットしない）。
- **大きく外れた結果は使わない。** ADS1115 の値が、粗値から換算した値と 200 cent 以上離れていたら、その結果は出力にも相対校正（9.3）にも使わない
  （`CFG_FUSION_PLAUSIBLE_CENT`）。通信エラーなどで壊れた値への備え。
  5.1 の「判定は粗値どうしで行う」は小さな閾値を使う急変判定の話で、この閾値は校正前の誤差（最大 約 100 cent）より十分大きいので矛盾しない。

### 5.4 定数

| 定数 | 値 | 決め方 |
|---|---|---|
| `T_STILL` | **8 LSB（約 13 cent）** | 粗サンプル `p` の LSB（理論換算 1.34mV ≒ 1.6cent）。静止時のウィンドウ内の `p` の幅（最大 5.6 LSB）に余裕を持たせた（13.1） |
| `T_JUMP` | **10 LSB（約 16 cent）** | `T_JUMP > T_STILL` は必須。静止時の誤判定は閾値 5 LSB 以上で 0 回だった（13.1）。小さいほど小さな音程変化を速く検出できる（10.4） |
| `MA_LEN` | 16 生サンプル（32µs） | 移動平均 `s` の窓の長さ。`p` の平均数と同じにする |
| `JUMP_CONFIRM` | **17 生サンプル（34µs）** | **`MA_LEN` + 1**。生サンプル 1 個のスパイクは移動平均を最大 `MA_LEN` サンプルの間しか動かさないので、これより 1 長くすれば単発スパイクでは確定しない |
| `DIRTY_CONFIRM` | **2 ウィンドウ**（約 2.3ms） | ADS モードでクリーンでないウィンドウがこの回数続いたら FAST へ移る（5.3）。1 にするとノイズで 1 回汚れただけで FAST に入る |
| `SMOOTH_MS` | **4 ms** | モード遷移時の段差を戻す時定数（5.5） |

### 5.5 モード遷移時の扱い

- **段差の戻し方**：切り替えた瞬間の出力の段差（切り替え前の出力 − 切り替え後の目標値）を「グライド量」として持ち、目標値に足して出力する。
  グライド量は時定数 `SMOOTH_MS` の 1 次で指数的に 0 に戻す。目標値は戻している間も `s`（FAST）や `ads_val`（ADS）に追従する。
- **ADS → FAST**: 即座に切り替える（速度が目的のため）。`offset` 補正があるので段差は小さい。
  `JUMP_CONFIRM` > `MA_LEN` なので、FAST に切り替わった時点で移動平均の窓は変化後の値で埋まっている。
  **出力は途中の値を経由せず、最初から変化後の音程になる。**
- **ADS → FAST（`DIRTY_CONFIRM` による遷移）**: 急ぎではないので、`SMOOTH_MS` かけて補間する。
  この時点の差（古い `ads_val` と粗値の差）は `T_JUMP` 未満。補間中も目標値は `s` に追従する。
- **FAST → ADS**: `offset` の残差ぶんの小さな段差（数 cent）が出る。`SMOOTH_MS` かけて補間する。
- **FAST に留まる時間**（入力が 1 回ステップして静止した場合。データシートの変換周期 1.057〜1.292ms から）：

  | 要素 | 最短 | 最長 |
  |---|---|---|
  | 変化を含むウィンドウの残り | ほぼ 0 | 1.292ms |
  | 次のクリーンなウィンドウ 1 つ | 1.057ms | 1.292ms |
  | I2C 読み出し | 0.07ms | 0.07ms |
  | **ADS モードへの復帰まで** | **約 1.13ms** | **約 2.65ms** |

  この後 `SMOOTH_MS` かけて ADS の値へ補間される。
- グライド・ビブラート中はウィンドウがクリーンにならないため、FAST モードに入って留まる
  （速い動きは急変判定で、遅い動きは `DIRTY_CONFIRM` で入る。5.3）。
  入力が止まれば、次のクリーンな変換で ADS モードに戻る。
  ウィンドウがクリーンなまま収まるほど遅い動き（1 ウィンドウあたり `T_STILL` 未満）は、ADS モードのまま変換ごとに追従する。
- `offset` はクリーンな変換のたび（約 1.16ms ごと）に取り直される。
  このため、ADC_AVDD のゆっくりしたドリフトは FAST モード中の誤差にほとんど残らない。

### 5.6 スケール

- 内部表現は **ADS1115 スケール**（1LSB = 187.5µV）に統一する。
- 粗値は `to_ads_scale()` で換算する。係数は 9.3 の自動相対校正で求める。
  理論上の初期値はゲイン ≒ 7.16（ADS LSB / 粗 LSB = 1.343mV / 0.1875mV、ADC_AVDD = 3.3V、分圧比 0.6 のとき）、オフセット 0。
- ADS1115 の絶対校正（9.2）`V = a × code + b` は、`voct_cent` に書く直前に 1 回だけ掛ける。
  フュージョンの内部（閾値、`offset`、相対校正）は ADS1115 の生の単位のまま扱い、絶対校正の値に影響されないようにする。
- V/OCT は 1V/oct のリニアなので、**対数変換は不要**。`cent = volt × 1200`。
- 音声側へは cent 単位の `float` で渡す（10 章）。RP2350 は単精度 FPU を持つ。

## 6. 未接続時の扱い（V/OCT）

**未接続を検知する仕組みは持たない。** ノードを 10MΩ でプルダウンするだけとし（2.2）、
ファームウェアは接続・未接続を区別せず、常に同じ処理（フュージョン、出力）を行う。
**未接続で使うことはほとんどない前提で、未接続時に 0V にならないことは許容する。**

- **未接続時は 0V にならない。約 0.2〜0.3V（約 240〜360cent ≒ 3 半音前後）になる。**
  - ADS1115 の入力の等価回路（データシート 図 26）では、同相インピーダンス ZCM は GND ではなく**約 0.7V** につながっている。
    ±6.144V レンジのシングルエンド（AINN = GND）では、ノードから見て ZCM 10MΩ が 0.7V へ、差動インピーダンス ZDIFF 22MΩ（Table 2）が GND へ入る。
  - ここに 10MΩ のプルダウンが付くので、典型値では次の電圧に落ち着く。

    ```
    V = 0.7V × (1/10MΩ) ÷ (1/10MΩ + 1/22MΩ + 1/10MΩ) ≈ 0.29V ≈ 340cent
    ```

  - ZCM・ZDIFF・0.7V はいずれも典型値で、個体差があり、温度でも動く。**未接続時の音程は正確でも安定でもない。**
  - プルダウンを小さくしても解決しない（1MΩ でも約 60mV 残り、相手の出力インピーダンスによる誤差が 10 倍になる。2.2）。
- **影響**：未接続のときは、つまみで決めた音程より約 3 半音高く鳴る。0V を出しているケーブルを挿すと、そのぶん下がる。
  0〜6000cent のクランプ（5.3）はこのずれには効かない（クランプは範囲外の値を収めるだけ）。
- **接続時への影響はない。** 0.7V 側へ引く電流（最大 約 70nA）は、相手の出力インピーダンス＋保護抵抗（約 2kΩ）で約 0.14mV（約 0.2cent）にしかならない。
- 実測の未接続時の読み値は 0.2747 V（約 330 cent）で、計算どおりだった（13.1）。
- **出力の `voct_cent` は 0〜6000cent にクランプする**（5.3）。0V 入力時の誤差が負側に出ても 0 に張り付くだけで、実害はない。
  共有変数の範囲（10.2）と、音声側の前提（`wtvco_audio_process.ja.md` §1.5）もこれに合わせている。
- **抜いた直後**は、ノードに直前の電圧が残り、（10MΩ ∥ ADS1115 入力）× 1nF（τ ≈ 4ms）で数十 ms かけて上記の電圧へ落ち着く。
  音程は短いグライドのように動く。許容する。
- **片側だけ挿したパッチケーブル**（V/OCT に挿して反対側を浮かせた状態）は、高インピーダンスのノードにつながるアンテナになり、
  ハムを拾って音程が揺れることがある。ケーブルを抜けば直るので許容する。
- 抜き挿しで入力が大きく動くと、通常どおり FAST モードに入り、静止すれば ADS モードに戻る。特別な処理は要らない。

## 7. PIC ファームウェア

PIC は**生値を読んで送るだけ**とする。校正値を持たず、受信もしない。
校正・スケーリング・スムージングはすべて RP2350 側で行う（8 章）。

### 7.1 クロック

- HFINTOSC 32MHz（Fosc = 32MHz）。
- 精度はデータシート 図 39-6 で **0〜60°C で ±2%**（60〜85°C で ±3%）。OSCTUNE による較正は行わない（7.4 参照）。
- 電源ピン直近に 0.1µF と 0.01µF を並列に置く（データシート 39.4.2 の注記。この精度の前提条件）。

### 7.2 ADC（ADCC）

| 項目 | 設定 |
|---|---|
| 分解能 | 12bit |
| 基準 | VREF+ = VDD、VREF− = VSS |
| 変換クロック | Fosc/32（TAD = 1µs） |
| モード | バースト平均（MD = 011。ADRPT / ADCRS で指定回数を平均） |
| 平均回数・右シフト | 下表。全入力を毎フレーム読む |
| 変換順 | **DEPTH → KNOB → FINE → COARSE → WT CV UNI → WT CV BI → FM CV UNI → FM CV BI**（下記） |
| 取得時間 | 各 ch の切り替え後に数 µs 以上（ワイパー・CV 入力のコンデンサがあるので短くてよい） |

**変換順の決め方**

- **CV 4 つを最後に連続させて**、送信直前の値にする（10.4）。
- **COARSE は UART の送信と重ならない位置に置く。** フレームは CV の変換の直後に送り始めるので、送信（約 180µs、7.4）は
  次のフレームの先頭の変換と重なる（変換が約 0.81〜0.91ms、送信の終わりが約 0.99〜1.09ms）。
  COARSE は最もノイズに敏感（1LSB ≒ 1.76cent）なので、送信中の変換を避ける。
- 先頭に DEPTH・KNOB・FINE（計 16 回、約 230〜260µs）を置くと、COARSE の変換は前のフレームの送信が終わった後になる。
  DEPTH・KNOB は低〜中精度、FINE は 1LSB ≒ 0.05cent なので、送信と重なっても問題ない。

**平均回数と右シフト（ADRPT / ADCRS）**

| 入力 | 平均回数（ADRPT） | ADCRS | 送る値（ADFLTR） | 平均回数の理由 |
|---|---|---|---|---|
| FREQ1 COARSE | 16 | 2 | 合計 / 4 = 平均 × 4 | RP2350 側の強い IIR（75ms）が数十フレームぶん平均するので足りる |
| FREQ1 FINE | 8 | 1 | 合計 / 2 = 平均 × 4 | 同上（IIR 20ms） |
| WT1 KNOB | 4 | 0 | 合計 = 平均 × 4 | 中精度。IIR あり |
| FM1 DEPTH | 4 | 0 | 合計 = 平均 × 4 | 低精度。IIR あり |
| WT1 CV UNI / BI | 4 / 4 | 0 | 合計 = 平均 × 4 | 低精度 |
| FM1 CV UNI / BI | 8 / 8 | 1 | 合計 / 2 = 平均 × 4 | ノイズが DEPTH 倍で音程に出るので WT CV より多め |
| **合計** | **56 回** | | | |

- ADCRS を平均回数に合わせて選び、**全入力が「平均値 × 4」（0〜16380）の同じスケール**になるようにする。
  12bit より細かい平均の情報を捨てずに 14bit で送る（7.3）。
- つまみの平均回数が少なめでも安定性は落ちない。ノイズの減り方は、PIC 側の平均回数ではなく、
  RP2350 側の IIR の時定数に入る総サンプル数で決まる（例：COARSE は 16 回 × 75 フレーム = 1200 サンプル）。
  PIC 側の平均は、1kHz に間引く前のアンチエイリアスの役割が主になる。

**1 フレーム内の変換時間**（データシート 39 章 ADC 特性）：

| 項目 | 値 | 出典 |
|---|---|---|
| 変換時間 TCNV | 14 TAD + 2 TCY = 14.25µs（TAD = 1µs、TCY = 125ns） | AD22 |
| 取得時間 TACQ | 2µs（典型） | AD23 |
| 1 回あたり | 14.25µs（取得なし）〜 16.25µs（毎回取得あり） | |
| 合計 56 回 | **約 0.81ms（ch 切り替え時だけ取得）〜 約 0.91ms（毎回取得）** | |

- 1 フレーム周期（1ms）に**約 1 割の余裕を残して収まる**。ADC と送信タイマはどちらも Fosc から作るので、HFINTOSC の誤差で比は変わらない。
- 実測では変換が約 0.90 ms で、約 1 割の余裕で 1ms に収まった（RA0 を変換中 High にしてオシロで測定。13.2）。
  計算の上限どおりなので、平均回数やチャンネルを増やす余地はほとんどない。
- 平均後の値は 14bit（平均 × 4）で送る（7.3）。下位ビットの扱いは RP2350 側で判断する。
- UART の送信は EUSART がバックグラウンドで行うので、変換と並行してよい。

### 7.3 フレーム形式

各値は **14bit**（送信値。平均 × 4、0〜16380。7.2）。**先頭バイトだけ bit7 = 1、それ以外は bit7 = 0** にして同期を取る。

| バイト | 内容 |
|---|---|
| 0 | ヘッダ：`0x80 \| seq`（seq = 0〜127 の連番） |
| 1, 2 | WT1 CV UNI：上位 7bit、下位 7bit |
| 3, 4 | WT1 CV BI |
| 5, 6 | FM1 CV UNI |
| 7, 8 | FM1 CV BI |
| 9, 10 | FREQ1 COARSE |
| 11, 12 | FREQ1 FINE |
| 13, 14 | WT1 KNOB |
| 15, 16 | FM1 DEPTH |
| 17 | チェックサム：バイト 1〜16 の合計の下位 7bit |

- 1 フレーム = 18 バイト。
- 値の復元：`raw = (上位バイト << 7) | 下位バイト`（各バイトの bit7 は 0）。
- **送信周期は 1ms（1kHz）**。タイマで一定周期にする（HFINTOSC の誤差で 0.98〜1.02ms）。
- seq は RP2350 側でフレームの取りこぼしを数えるのに使う。

### 7.4 UART 設定

| 項目 | 設定 |
|---|---|
| 形式 | 8N1、TX のみ |
| ボーレート | 1Mbps（BRG16 = 1、BRGH = 1、SPBRG = 7。32MHz / (4 × 8) = 1MHz で割り切れる） |
| 1 フレームの送信時間 | 18 バイト × 10bit = 180bit 時間 = **約 180µs** |

- 分周比が割り切れるので、ボーレート生成器の丸め誤差はない。誤差要因は HFINTOSC の精度（±2%、7.1）だけになる。
- 受信側の RP2350 は水晶基準で、1Mbps を正確に作れる（clk_peri 150MHz / (16 × 1MHz) = 9.375 = 整数 9 ＋ 小数 24/64）。
- ±2% のずれは 8N1 の許容範囲に収まる。実測の周期の誤差は +0.03〜+0.19% で、フレーミングエラー・チェックサムエラーは出なかった（13.2）。
  OSCTUNE による較正は不要。
- 送信は EUSART の割り込みで 1 バイトずつ行い、送信中も次のフレームの変換を進める。

## 8. RP2350 側の PIC 受信処理と値の変換

### 8.1 受信

- UART0、RX = GP1（TX ピンは割り当てない。2.6）、1Mbps、8N1。
  pico-sdk の `hardware_uart` で初期化し、受信 FIFO を core1 のループから直接読む（割り込みなし）。軽く、`Serial1` のように GP0 を UART に取られない。
- bit7 = 1 のバイトでフレームの先頭とみなし、18 バイト揃ったらチェックサムを検証する。
- チェックサム不一致、途中で bit7 = 1 のバイトが来た、などのフレームは**丸ごと捨てる**。
- 各バイトのエラーフラグ（フレーミング・ブレーク・オーバーラン）、チェックサムエラー、seq の欠番をそれぞれ数え、USB コンソールの `pic` コマンドで見られるようにする。
- 受信は 100 µs ごとに行う（10.1）。フレームは 1 ms 周期で、受信 FIFO（32 バイト）は 1 Mbps で約 320 µs ぶんあるので、間引いても取りこぼさない。

### 8.2 フレームが途絶えたとき

| 経過時間（最後の正常フレームから） | 扱い |
|---|---|
| 〜 `T_PIC_HOLD`（100ms） | **最後の値を保持** |
| `T_PIC_HOLD` 以降 | **0 とみなす**（下表） |

| 値 | 0 とみなしたときの出力 |
|---|---|
| `coarse_cent` | **3600cent（C3）**。C0 まで下がって超低音が出るのを避けるため、COARSE だけは 0 ではなく C3 とする |
| `fine_cent` | 0cent（つまみ中央相当） |
| `wt_cv` | 0.0（両入力とも変調 0。UNI は 0V、BI は 2.5V 相当。**BI を生値 0 とみなさないこと**（−0.5 になる）） |
| `wt_knob` | 0.0 |
| `fm_cent` | 0cent（FM CV の両入力とも変調 0、DEPTH 0 相当。BI を生値 0 とみなさないこと） |

- 起動直後は「最後の値」がないので、最初の正常フレームが届くまでは 0 とみなす。
- 正常フレームが再び届けば、そのまま通常動作に戻る（スムージングを通す）。
- この挙動により、**PIC を載せていない状態でも、つまみ以外（V/OCT、音声出力）は動作し、試験できる。**
  このとき C3 ＋ V/OCT の音程で鳴る（V/OCT も未接続なら、6 章のぶん約 3 半音高くなる）。

### 8.3 つまみの変換

| つまみ | 変換 | 出力 |
|---|---|---|
| FREQ1 COARSE | `coarse_cent = raw / 16380 × 7200` | 0〜7200 cent（C0〜C6） |
| FREQ1 FINE | `fine_cent = (raw / 16380 − 0.5) × 200` | −100〜+100 cent |
| WT1 KNOB | `raw / 16380` | 0.0〜1.0 |
| FM1 DEPTH | `k = raw / 16380`、`fm_depth = 2400 × k²` | 0〜2400 cent/V（2 乗カーブ） |

- レシオメトリックなので**校正は不要**。
- 範囲外の値はそれぞれの範囲にクランプする。

**FREQ1 COARSE（安定性最優先）**

ADC の 1LSB ≒ 1.76cent（送信値の 1LSB ≒ 0.44cent）なので、ADC の値が 1LSB ふらつくだけで音程の揺れとして聞こえる。次の順で処理する。

1. **強めの 1 次 IIR**（時定数 75ms）でノイズを落とす。
2. **ヒステリシス（不感帯）**を掛ける。出力値との差が `COARSE_HYST`（4.5cent ≒ 送信値で 10LSB）を超えたときだけ出力を更新する。
   - 不感帯のせいで数 cent のずれが残るが、これは FINE で直す前提とする。
   - つまみを回している最中は大きく動くので、不感帯は気にならない。
3. 出力は更新時にスムージング（10.3）を通るので、段差は聞こえない。

**FREQ1 FINE**

ADC の 1LSB ≒ 0.05cent（送信値で 0.012cent）と細かいので、ふらつきは問題になりにくい。1 次 IIR（時定数 20ms）と小さなヒステリシス（0.1cent）で十分。

**WT1 KNOB（中精度）**

1 次 IIR（時定数 15ms）と、大きめのヒステリシス（0.004。WT の全域が 1.0）でよい。

**FM1 DEPTH（低精度）**

- 直線だと、ビブラートでよく使う 10〜50cent/V がつまみの下端 2% ほどに押し込まれるので、**2 乗カーブ**にする。

  | つまみ位置 k | DEPTH |
  |---|---|
  | 0.1 | 24 cent/V |
  | 0.3 | 216 cent/V |
  | 0.5 | 600 cent/V |
  | 約 0.71 | 1200 cent/V |
  | 1.0 | 2400 cent/V |

- IIR とヒステリシスは `k`（カーブを掛ける前）に掛ける。1 次 IIR（時定数 20ms）と小さなヒステリシス（k に対して 0.001）でよい。
- 送信値の 1LSB あたりの DEPTH の変化は最大でも約 0.3cent/V（k = 1 付近）。

**時定数と不感帯の決め方**

上の値は、実測のノイズ（13.2）と聴感で決めた。IIR は 1 フレーム（1 ms）ごとに `y += a (x − y)`、`a = 1 − exp(−1 ms / τ)` で更新する。
USB コンソールの `tune` コマンドで、書き込みなしに（RAM 上だけで）値を変えて試せる。

### 8.4 CV 入力の共通変換（WT CV・FM CV）

WT CV・FM CV とも、UNI と BI の送信値を次の式で電圧（変調量）に換算して合算する。**感度は両入力で同じ。**

```
v_uni = (raw_uni − zero_uni) × gain_uni       // V。0V 基準の変調量
v_bi  = (raw_bi  − zero_bi ) × gain_bi        // V。2.5V 中心からの変調量
cv_v  = clamp(v_uni + v_bi, −2.5, +7.5)       // V
```

| 係数 | 意味 | 既定値（校正前） | 求め方 |
|---|---|---|---|
| `zero_uni` / `zero_bi` | ゼロ点（変調 0 とみなす送信値） | UNI：0、BI：8190（送信値の中点 = 2.5V） | ゼロ点校正（9.4） |
| `gain_uni` / `gain_bi` | 送信値 1LSB あたりの電圧 | 5V / 16380（≒ 0.305mV） | ゲイン校正（9.4、任意） |

- 係数は 4 入力（WT CV UNI・BI、FM CV UNI・BI）それぞれに持つ。
- **個別の入力ではクランプしない。** BI の負側を残すため、また未接続時のノイズを片側だけ切ると平均がずれるため。
  合算後の範囲外の値だけを −2.5〜+7.5V に収める。
- 入力の負荷による約 2% のゲイン誤差は、ゲイン校正で吸収する（2.5）。
- 未接続時は UNI が 0V（プルダウン）、BI が 2.5V（バイアス）になり、ゼロ点を引いた結果はどちらも変調 0。
- BI のバイアス（VDD / 2）は送信値の中点なので、既定のゼロ点（8190）でも、未接続時はバス電圧によらずほぼ 0 になる。
  残るずれ（抵抗の誤差、ADC のオフセット、リーク電流）はゼロ点校正で打ち消す。

### 8.5 WT CV の変換

1. WT CV の UNI・BI を 8.4 で合算し、`cv_v_wt`（−2.5〜+7.5V）を得る。
2. `wt_cv = cv_v_wt / 5.0` として正規化する（1V = 0.2、範囲 −0.5〜+1.5）。
3. 1 次 IIR でスムージングする（時定数 2 ms、fc ≈ 80 Hz。中速の変調を鈍らせずに、1 ms ごとの段差とノイズを落とす）。
4. **ここではクランプしない。** 0〜1 にクランプすると、BI の負側の変調が消える。
   クランプは音声側の最終段で 1 回だけ行う（10.3）。

- 両方未接続なら `wt_cv = 0`。
- 音声側は `wt = clamp(wt_knob + wt_cv, 0, 1)` で合成する（10.3）。

### 8.6 FM CV の変換

1. FM CV の UNI・BI を 8.4 で合算し、`fm_v`（−2.5〜+7.5V）を得る。
2. `fm_v` に 1 次 IIR でスムージングする（WT CV と同じ時定数 2 ms）。ノイズは DEPTH 倍で音程に出るが、
   DEPTH 中央・CV 未接続での揺れは ±0.3 cent で、聞こえない（13.2）。
3. **`fm_cent = fm_depth × fm_v`**（`fm_depth` は 8.3。0〜2400cent/V）。範囲は −6000〜+18000cent。
4. **ここではクランプしない。** 音程のクランプは音声側で行う（10.3）。

- 両方未接続なら `fm_cent = 0`。DEPTH = 0 でも 0。
- **低速の変調専用**（2.5）。精度は低精度として許容し、正確な 1V/oct の追従は求めない。
- 音声側は `fm_cent` を音程の和に加える（1.3、10.3）。

## 9. キャリブレーション

### 9.1 構成

RP2350-Zero の USB CDC で PC のターミナルと直接やり取りする（USB コンソール。10.1）。
コマンド処理は core1 のループ内で行い、音声合成を止めない。**PIC 側の校正はない。**

| コマンド | 内容 |
|---|---|
| `calmode on` / `off` | 校正モードに入る / 出る。以下のコマンドは校正モード中だけ使える |
| `vcal <mV>` | V/OCT に与えた電圧の実測値を入力し、1 点を記録する（9.2） |
| `vcal fit` / `clear` / `list` | 記録した点から係数を求める / 点を消す / 点を表示する |
| `czero` | CV 入力のゼロ点を測る（9.4） |
| `calsave` | すべての校正値をフラッシュに保存する（9.5） |
| `calshow` / `caldefault` | 現在の値を表示する / 理論値に戻す（保存はしない） |

### 9.2 ADS1115 の絶対校正（手動・DMM 使用）

基準電圧源は精度が高い必要はない。**安定していればよい**（DMM で実測した値を入力するため）。

1. `calmode on` で校正モードに入る。
2. V/OCT ジャックに電圧を与える。ジャックを GND に短絡すれば 0V 点が得られる。
3. その電圧を DMM で実測する。
4. 実測値（mV）を `vcal <mV>` で入力する。RP2350 は 0.5 秒間の ADS1115 の値を平均して記録する。
   その間に値が揺れていたら（入力が安定していない）、その点は捨ててエラーを表示する。
5. 2 点以上（できるだけ離す。例：1V と 4V）繰り返す。
6. `vcal fit` で、最小二乗によりゲイン・オフセットを求める。次の場合は採用しない：点が 2 点未満、点どうしが 1V 以上離れていない、
   ゲインが理論値から 2% 以上ずれている（読み違いや入力ミスの可能性が高い）。
7. `calsave` で保存し（9.5）、`calshow` で確認する。

参考：ADS1115 単体の誤差はゲイン誤差 典型 0.01%・最大 0.15%、シングルエンドのオフセット 典型 ±3LSB（データシート 電気的特性、FS = ±2.048V での値）。
最大ゲイン誤差 0.15% は 5V（6000cent）で約 9cent に相当するので、校正は必須。

### 9.3 粗 ADC ↔ ADS1115 の相対校正（自動）

ADS モード中は、同じ電圧に対する `ads_result` と `ref` のペアが常に手に入る。
これを蓄積して最小二乗を回せば、**外部機器なしで換算係数（`to_ads_scale` のゲイン・オフセット）を維持できる。**

- **ペアの収集**：フュージョンが採用したクリーンな変換（5.3）ごとに、（ウィンドウの粗値の平均、ADS1115 の値）を 1 ペア集める。
- **区間に分ける**：電圧が偏ると精度が落ちるため、粗値の範囲（0〜4095）を 8 区間に分け、区間ごとに平均する
  （4096 ペアまでは単純平均、以後は 1/4096 の指数平均）。
- **計算**：64 ペア以上集まった区間を 1 点として最小二乗を解く。
  両端の区間が 600 LSB（約 1.3V）以上離れていればゲインとオフセットを、そうでなければオフセットだけを更新する。
  理論値から ±20% を超えるゲインは採用しない。64 ペアごと（約 74 ms ごと）に計算し直す。
- 学習結果は RAM 上で随時更新する。**自動ではフラッシュに保存しない**（9.5）。
- 起動直後は前回保存値を使う。保存値がなければ理論値（5.6）を使う。
- 実機では約 15 秒で収束した（13.1）。

### 9.4 CV 入力（WT CV・FM CV）の校正

#### ゼロ点校正（推奨。DMM 不要）

未接続時の送信値を「変調 0」の点（`zero_*`、8.4）として測って保存する。
BI のバイアス抵抗の誤差（最大 約 25mV）、PIC の ADC のオフセット、ピンのリーク電流による未接続時のずれを打ち消す。
FM CV ではずれが DEPTH 倍で音程に出る（DEPTH 最大で 25mV ≒ 60cent）ので、**FM CV では実質必須**。WT CV も同じ手順で一緒に取る。

1. `calmode on` で校正モードに入る。
2. **すべての CV 入力（WT CV UNI・BI、FM CV UNI・BI）から何も抜く。** V/OCT とつまみは関係しない。
3. `czero` を送る。RP2350 は PIC から届く送信値を、入力ごとに 1 秒（約 1000 フレーム）平均する。
4. 妥当性を確認する。UNI は 0 から、BI は 8190 から ±400LSB（≒ ±120mV）以上離れていたら、
   その入力は採用せずエラーを表示する（何か挿さっている、配線不良などの可能性）。
5. 4 入力の測定値と、既定値からの差（mV）を表示する。
6. `calsave` で保存する（9.5）。

- 基板や PIC を交換したら取り直す。温度で多少動くが、低精度用途として許容する。
- UNI はプルダウンで 0V 付近にあるので、ADC のオフセットが負のときは送信値が 0 に張り付き、ゼロ点に現れない（数 LSB 程度。許容）。
- リーク電流によるずれは未接続時にだけ現れ、接続すると相手の低いインピーダンスでほぼ消える。
  ゼロ点にリーク分が含まれていた場合、接続時はその分だけ逆向きにずれる（典型 0.5mV ≒ DEPTH 最大で 1.2cent、最悪 12.5mV）。許容する。

#### ゲイン校正（任意・DMM 使用）

9.2 と同じ手順で、各入力に 2 点の電圧（例：0.2V と 4.8V）を与え、**入力ごとに**ゲイン（`gain_*`）を求める。

- ゲイン = 2 点の電圧の差 / 送信値の差。ゼロ点はゼロ点校正の値を使い、ここでは求めない
  （BI でも 2 点の差だけで計算できるので、2.5V の基準電圧は不要）。
- RP2350 は PIC から届いた送信値を使って計算する。
- **現在のファームウェアには、ゲイン校正のコマンドはない。** ゲインは理論値（5V / 16380）で動作する。
  低精度用途なので、約 2% のゲイン誤差（2.5）は許容している。保存データにはゲインの欄があり、後からコマンドを足せる。

### 9.5 保存

RP2350 には EEPROM がないため、フラッシュに保存する（arduino-pico の EEPROM ライブラリ。フラッシュの 1 セクタ）。

- **フラッシュの消去・書き込み中は、XIP が止まり、両コアが待たされる。演奏中に行うと音が途切れる。**
- **保存の前に、音声側へミュートを要求する**（10.2 の `audio_mute_req` / `audio_mute_ack`）。
  音声側の出力は DMA が SRAM のリングを読み続ける方式なので、何もせずに保存するとリングの残りが繰り返し鳴り、ブザー音になる。
  1. `audio_mute_req = 1` にする。
  2. `audio_mute_ack == 1` になるまで待つ（音声側がフェードアウトしてリングを 0 で埋める）。50ms 来なければ保存を中止してエラーを表示する。
  3. フラッシュに書く。
  4. `audio_mute_req = 0` に戻す（音声側が通常動作に戻る）。
- 保存は**校正モード中のコマンド実行時だけ**行う（手動校正・ゼロ点校正の結果、自動相対校正の現在値の保存）。
- 通常動作中に自動で保存する処理は**実装しない**。

| 項目 | 内容 |
|---|---|
| ADS1115 | ゲイン、オフセット（手動校正） |
| 粗 ADC | ADS1115 スケールへの換算ゲイン、オフセット（自動相対校正） |
| WT1 CV UNI・BI | 入力ごとのゼロ点（ゼロ点校正）、ゲイン（現在は理論値） |
| FM1 CV UNI・BI | 入力ごとのゼロ点（ゼロ点校正）、ゲイン（現在は理論値） |
| 整合性 | 識別子とチェックサム（FNV-1a）を付け、壊れていたら理論値のデフォルトに戻す |

## 10. 音声側（core0）とのインタフェース

### 10.1 コア分担

| コア | 担当 |
|---|---|
| core0 | 音声合成、I2S 出力（PCM5102A。自前の PIO＋DMA リング）。**このループ専用で、他の処理・割り込みを入れない** |
| core1 | 粗 ADC＋DMA、I2C（ADS1115）、フュージョン、PIC 受信、つまみ・WT CV・FM CV の変換、校正コマンド |

**core1 ループの時間制約**

- **ループ 1 周を 10µs 以内に収める。** V/OCT の出力はループ 1 周ごとに更新されるので、1 周の長さがそのままレイテンシに乗る。
- 待ちの発生する処理は使わない：`Wire`（4.4）、`delay()` など。
- **処理を間引く。** V/OCT（粗 ADC・ADS1115・フュージョン）は毎周処理する。PIC の受信と値の変換は 100 µs ごと、USB コンソールは 250 µs ごと、
  コマンドの実行は 1 周に 1 つまでとする。重い処理（最小二乗の計算など）は、1 周あたりの量を区切って複数周に分ける。
- **USB コンソールは arduino-pico の `Serial` を core1 で使わない。** `Serial` の各メソッドは USB のロックを待ってから `tud_task()` を実行するので、
  core1 を最大 2.5 ms 止めた。そこで、USB のロックは「取れたら使う」だけにして、CDC の FIFO を直接読み書きする
  （`tud_task()` は arduino-pico が core0 で 1 ms ごとに実行するものに任せる）。
- **core1 の SysTick 割り込みを止める**（`core1_disable_systick = true`）。arduino-pico が `rp2040.getCycleCount()` のためだけに入れている割り込みで、
  10 µs の予算には不要。
- 入力部の割り込み（RDY の GPIO 割り込み、DMA 完了など）は **core1 で登録する**。core0 は音声専用で、割り込みで止められると出力がアンダーランする（`wtvco_audio_process.ja.md` §1.11）。
- 実測では、1 周の 97% が 5 µs 以内、99.55% が 10 µs 以内だった（13.1）。

### 10.2 共有変数

core1 が書き、core0 が読む（`audio_mute_ack` だけは逆向き）。すべて 32bit の単一変数（`volatile float` / `volatile uint32_t`）とし、
1 回の読み書きで完結させる（排他制御は不要）。

| 変数 | 型 | 単位・範囲 | 更新 |
|---|---|---|---|
| `voct_cent` | float | 0〜6000 cent（クランプ済み。未接続時は 0 にならない。6 章） | core1 ループ 1 周ごと（10µs 以内） |
| `coarse_cent` | float | 0〜7200 cent（C0 基準） | 更新時（ヒステリシス超え） |
| `fine_cent` | float | −100〜+100 cent | 1ms ごと |
| `wt_cv` | float | −0.5〜+1.5（UNI ＋ BI の合算。**クランプ前**。8.5） | 1ms ごと |
| `wt_knob` | float | 0.0〜1.0 | 1ms ごと |
| `fm_cent` | float | −6000〜+18000 cent（FM CV × DEPTH。**クランプ前**。8.6） | 1ms ごと |
| `status` | uint32_t | ビットフラグ（FAST/ADS モード、ADS 縮退、PIC 途絶など） | 随時 |
| `audio_mute_req` | uint32_t | 0 / 1。フラッシュ保存前のミュート要求（9.5） | 保存時のみ |
| `audio_mute_ack` | uint32_t | 0 / 1。**core0 が書き、core1 が読む**。ミュート完了の応答 | 保存時のみ |

### 10.3 音声側での使い方

- 音程は 1.3 の式で計算する。
- WT 位置は `wt = clamp(wt_knob + wt_cv, 0, 1)`（KNOB が基準、CV が変調量。UNI は上向き、BI は上下）。
  **クランプはここで 1 回だけ行う**（入力部はクランプせずに渡す。8.5、8.6）。詳細は音声側で決める。
- FM は `fm_cent` を音程の和に加える（1.3）。音程のクランプは音声側で行う。
  `fm_cent` のスムージングは、つまみの音程（COARSE＋FINE）とは**別に**掛ける（つまみ用の長い時定数で LFO の変調を鈍らせないため）。
- `coarse_cent`、`fine_cent`、`wt_knob`、`wt_cv`、`fm_cent` は階段状に変わるので、**サンプルごとに補間するか 1 次ローパスを掛けてから使う**
  （そのまま使うとジッパーノイズが出る）。
- `voct_cent` は音声側が**毎サンプル読む**（`wtvco_audio_process.ja.md` §1.5）。
  V/OCT の反映がオーディオのブロック長に縛られない。

### 10.4 レイテンシ収支

**V/OCT（ノートオンから core0 が値を得るまで）**

半音以上の音程変化の場合。

| 要素 | 最悪 | 典型 | 根拠 |
|---|---|---|---|
| 生サンプル（2µs ごと） | 2µs | 1µs | 500kSPS、ラウンドロビンなし（3.1） |
| 移動平均 `s` が `T_JUMP` を超えるまで | 6µs | 2µs | 下記 |
| `JUMP_CONFIRM` 17 生サンプル | 34µs | 34µs | 5.4 |
| core1 ループ 1 周（出力の更新間隔） | 10µs | 5µs | 10.1 |
| **合計** | **約 52µs** | **約 42µs** | |

- 移動平均が `T_JUMP` を超えるまでの時間は変化の大きさで決まる。`T_JUMP` = 15cent のとき、
  半音（100cent）の変化で 3 生サンプル（6µs）、2 半音以上なら 1〜2 生サンプル。
  それより小さい変化ではもっと長くかかる（例：20cent で 13 生サンプル = 26µs）。
- 入力回路の時定数（1kΩ × 1nF = 1µs、バッファ後の分圧は 6kΩ で ADC のサンプリングに十分低い）は上表に比べて無視できる。

音声側（出力リング、PCM5102A、出力バッファを含む）は最悪 約 167µs・典型 約 162µs で、ノートオンから音声出力（OUT1）まで
**合計 最悪 約 219µs・典型 約 204µs**（`wtvco_audio_process.ja.md` §1.11）。要求の 500µs に対して、最悪で約 281µs の余裕がある。
実測は約 210µs だった（13.1）。

**V/OCT の高精度（ADS モード）への復帰**

5.5 の表の通り、ステップ後 約 1.13〜2.65ms で ADS1115 の値に戻り、その後 `SMOOTH_MS` かけて補間される。
この間は粗精度（数 cent〜十数 cent）だが、音程の大きなずれはない。

**WT CV・FM CV（入力の変化から共有変数まで）**

7.2 の構成（フレーム周期 1ms、56 回）での値。

| 要素 | 最悪 | 典型 | 根拠 |
|---|---|---|---|
| 次の CV 変換まで | 1.02ms | 0.5ms | フレーム周期 1ms（HFINTOSC ±2%）。CV は毎フレーム 1 回 |
| CV のバースト変換（WT UNI 4 ＋ BI 4 ＋ FM UNI 8 ＋ BI 8 回） | 0.39ms | 0.35ms | 7.2（14.25〜16.25µs × 24）。最悪は最初に変換する WT CV UNI |
| UART 送信（18 バイト） | 0.18ms | 0.18ms | 7.4。CV 4 つを最後に変換して直後に送る |
| RP2350 の受信処理 → 共有変数 | 0.01ms | 0.005ms | core1 ループ 1 周 |
| **合計** | **約 1.6ms** | **約 1.0ms** | ＋ 入力の RC（τ ≈ 0.2ms、2.5）＋ 1 次 IIR（8.5、8.6） |

音声側でさらにコントロール周期（≤ 167µs）＋出力（約 167µs）＋スムージング（2ms）が加わる。中速の要求には十分。

**つまみ**

CV と同じ経路で、変換順が先のぶん長くなる（最初に変換する DEPTH で合計 最悪 約 2.1ms、COARSE で約 1.9ms）。
実際の応答は IIR の時定数（COARSE 50〜100ms など。8.3）で決まり、経路の遅れは無視できる。

## 11. 起動・エラー処理

### 11.1 起動シーケンス（core1）

1. 粗 ADC を設定し、DMA リングバッファへの常時サンプリングを開始する（最初に音が出せる状態を作る）
2. フラッシュから校正値を読み出す。チェックサム不一致ならデフォルト値
3. GP1 の内部プルアップを有効にし（2.5）、UART0（`hardware_uart`、RX = GP1。2.6、8.1）の受信を開始する。最初の正常フレームまで PIC 由来の値は 8.2 の既定値（COARSE は C3）
4. I2C0 を `hardware_i2c` で初期化し（`Wire` は使わない。4.4）、ADS1115 に Config・Hi_thresh・Lo_thresh を書く
   （起動時の設定だけは待ち合わせで書いてよい）
5. 書いた Config を読み返して一致を確認する（**OS ビット（bit 15）は変換状態を示すので比較から除く**。データシート Table 9）。ポインタを Conversion に戻す
6. RDY（GP10）の GPIO 割り込みを **core1 から**有効化する
7. 最初のクリーンな変換が来るまでは **FAST モードで動作**する

### 11.2 エラー処理

| 事象 | 対応 |
|---|---|
| ADS1115 が応答しない（起動時） | **粗 ADC 単独動作に縮退**し、`status` にフラグを立てる。音は出続ける。1 秒ごとに再初期化を試みる |
| RDY が 50ms 来ない | ADS1115 を再初期化する。失敗したら縮退し、1 秒ごとに再試行する |
| I2C がバスハング（SDA が Low のまま） | SCL を 9 回トグルして解放 → STOP → 再初期化 |
| 読み出しが次の RDY に間に合わない | その変換は捨てる。ウィンドウ統計もリセットして次のウィンドウへ |
| I2C の読み出しが中断された（TX_ABRT、NACK など） | その変換は捨てる（4.4）。`TX_ABRT` を解除して次の変換を待つ。続けば「RDY が来ない」と同じ扱い |
| I2C の結果待ちの間に入力が動いた | その結果は捨てる（5.3）。急変判定は並行して進む |
| 粗 ADC の FIFO ERR / DMA のオーバーラン | 該当サンプルを直前の値で置き換える（3.2）。統計が壊れたウィンドウは破棄する |
| PIC のフレームが壊れている | そのフレームを捨てる（8.1）。エラー数を数える |
| PIC のフレームが途絶えた | 8.2 の通り（最後の値を保持 → 0 とみなす） |

**縮退時も必ず音が出続けることを最優先とする。** 無音になる実装にしない。

- **再初期化は core1 を止めずに行う。** Config・Hi_thresh・Lo_thresh・ポインタの 4 回の書き込みを I2C の FIFO に積むだけにする
  （設定の読み返しは起動時だけ）。
- 縮退中と再初期化中は、フュージョンを FAST モードにして粗 ADC で動かす。再初期化の直後の変換結果は信用できないので、最初の 2 回は捨てる。
- 実機で、RDY の停止から約 51 ms での復帰と、AE バスの電源断 → 縮退 → 電源が戻って自動復帰、を確認した（13.3）。

## 12. 既知の誤差要因

| 要因 | 大きさ | 扱い |
|---|---|---|
| 相手モジュール出力インピーダンスのばらつき（V/OCT） | ADS1115 の入力インピーダンス（同相 10MΩ、±6.144V レンジ）に対し約 0.01〜0.02% | 無視可（1cent 未満） |
| ADS1115 のゲイン誤差・オフセット | 最大 0.15%（≒ 5V で 9cent）、典型 ±3LSB | 手動校正で吸収（9.2） |
| プルダウン 10MΩ による GND 引き込み | 約 0.02% | 校正で吸収 |
| 未接続時の V/OCT の読み値 | 約 0.2〜0.3V（約 240〜360cent）。ADS1115 の入力が約 0.7V 側へ引くため。個体差・温度変化あり | **許容する**（未接続ではほぼ使わない）。接続時への影響は約 0.2cent で無視可。実測 0.2747V（6 章、13.1） |
| 粗 ADC の基準（ADC_AVDD）のノイズ・ドリフト | ADC_AVDD は 3V3 にフィルタなしで直結（2.6）。`p` の標準偏差 0.63〜0.78 LSB（13.1） | FAST モード中のみ影響。ドリフトは `offset` の更新で消える |
| 粗 ADC の分圧抵抗の誤差 | 抵抗精度ぶんのゲイン誤差 | 自動相対校正で吸収 |
| ADS1115 変換レートのばらつき | ±10% | RDY 基準で処理するため無害 |
| FAST モード中の絶対精度 | 数 cent〜十数 cent | ステップ後は約 1.1〜2.7ms 間のみ（5.5）。グライド中など入力が動き続けている間は続く。許容 |
| つまみの電源（5V バス）の変動 | — | レシオメトリックのため相殺される |
| FREQ1 COARSE の分解能・ノイズ | ADC の 1LSB ≒ 1.76cent（送信値は 14bit で 0.44cent 刻み） | PIC 側の平均化、強めの IIR、ヒステリシスで対処（8.3）。残る数 cent は FINE で直す |
| FREQ1 COARSE の摺動ノイズ | 可変抵抗の品質次第 | 良品を使う。ワイパーの容量を増やす（2.5） |
| FREQ1 FINE の分解能 | ADC の 1LSB ≒ 0.05cent | 問題なし |
| CV（WT・FM）の 5V バス変動 | バスの変動率ぶん | 低精度用途のため許容 |
| CV（WT・FM）の入力の負荷（UNI のプルダウン、BI のバイアス）によるゲイン誤差 | 約 2%（UNI は 0V 中心、BI は 2.5V 中心） | ゲイン校正で吸収（任意）。BI の中点はずれない |
| CV BI のバイアス抵抗の誤差 | 1% 品 2 本で最大 約 25mV（WT 0.005、FM は DEPTH 最大で約 60cent） | ゼロ点校正で打ち消す（9.4） |
| PIC ピンのリーク電流（CV 未接続時） | 最悪 12.5mV、典型 0.5mV | ゼロ点校正で打ち消す。接続時は逆向きに同程度残る（典型 FM 1.2cent。9.4） |
| CHOLD との電荷分配（CV） | 最悪 約 1.4mV（ch 切り替え直後の 1 回目） | ピン直近の 100nF で抑える。無視可（2.5） |
| FM CV の分解能・ノイズ | ADC の 1LSB ≒ 2.9cent、送信値の 1LSB ≒ 0.73cent（DEPTH 最大） | PIC 側の平均化（8 回）と IIR（8.6）。低精度として許容 |
| FM の感度（DEPTH）の精度 | ゲイン誤差 約 2% ＋ バス変動 ＋ つまみの位置 | 低精度として許容。正確な 1V/oct の追従は求めない |

## 13. 検証結果

試作機 2 台での実測と、PC 上のシミュレーション・テストの結果をまとめる。
特に断りのない値は 1 台目のもの。

### 13.1 V/OCT

| 項目 | 結果 |
|---|---|
| 粗 ADC | 500 kSPS。粗サンプル `p`（16 平均）の標準偏差 0.63〜0.78 LSB（1.0〜1.3 cent）。I2S を止めると 0.48 LSB で、BCK（GP14）の寄与は小さい |
| 粗 ADC と ADS1115 の関係 | 粗 ADC（理論換算）の読み ≈ 0.979〜0.982 × V ＋ 約 20 mV。自動の相対校正（9.3）で吸収した。区間ごとの残差は ±2〜4 cent（RP2350 の ADC の非直線性） |
| 自動の相対校正の収束 | 約 15 秒で収束し、FAST モードの補正値の誤差は 76 cent（理論値のまま）から ±4 cent になった |
| ADS1115 | 約 860 回/s。RDY の周期は 1148〜1171 µs（個体ごとに違う）。信号源をつないだときのノイズは標準偏差 0.13 cent、p-p 1 cent 未満 |
| ADS1115 の絶対校正（9.2） | 約 1 V と約 4 V の 2 点で校正。ゲインの理論値との差は 1 台目 +0.084%、2 台目 +0.130%。校正後、4.001 V の入力が 4801.04 cent（理論 4801.2 cent）になった |
| 未接続時の V/OCT（6 章） | ADS1115 で 0.2747 V（約 330 cent）、粗 ADC（理論換算）で 0.288 V。計算（約 0.29 V）どおり。ADS1115 の設定前（電源投入時の既定状態）は約 0.02 V。未接続時の ADS1115 のノイズは標準偏差 2.3 LSB（0.5 cent）、p-p 15 LSB（3.4 cent）で、信号源をつないだとき（0.58 LSB）より大きい（ノードが高インピーダンスのため） |
| `T_STILL` / `T_JUMP` の根拠（5.4） | 未接続（0 V 付近）で、36 個の `p` で区切ったウィンドウ 2.6 万個の幅は最大 5.6 LSB。急変判定を模擬した誤判定は、閾値 5 LSB 以上で 0 回（4 LSB では 30 秒に 7 回）。中間電圧ではノイズが約 15% 大きい。これらから `T_STILL` = 8 LSB、`T_JUMP` = 10 LSB とした |
| 静止した電圧での誤判定 | 1.04 V / 2.51 V / 3.99 V を各 30 秒（約 2.6 万ウィンドウ）入力。急変による FAST への遷移は 0 回、クリーンでないウィンドウは 0〜1 個で、ADS モードのまま。`voct_cent` の変動は 0.2〜0.5 cent。2 台目も 1 / 2.5 / 4 V で 0 回 |
| フュージョンの応答（シミュレーション） | 1 サンプルだけの +500 LSB のスパイクでは FAST に入らない。半音以上のステップは 40 µs で新しい音程になる。±8 cent・400 Hz の揺れ（`T_JUMP` 未満でウィンドウは汚れる）では FAST に移り、取り残されない（5.3） |
| ADS モードへの復帰 | ステップ後 約 1.8 ms（5.5 の見積もり 1.13〜2.65 ms の範囲内） |
| ノートオン → OUT1 | **約 210 µs**。CV 源の出力が段を切り替える瞬間をトリガにして、オシロで測った（見積もり 最悪 219 µs、要求 500 µs 以内。10.4） |
| core1 のループ 1 周 | 97% が 5 µs 以内、99.55% が 10 µs 以内、最大 約 30 µs（コンソールのコマンドを実行しない周） |

| 項目 | 結果 |
|---|---|

### 13.3 電源・障害処理

| 項目 | 結果 |
|---|---|
| 電源投入・断（2.4） | 5V バスと RP2350 の 3V3 をオシロで同時に観測。投入時はバスが 3.63 V を超える時点で IOVDD が 2.5 V 以上あり、断のときは IOVDD が 2.5 V を下回る時点でバスが 3.63 V 以下。どちらも条件を満たす（USB 未接続） |
| USB を挿したまま AE バスの電源を切る（2.1） | RP2350 は動き続け、ADS1115 と PIC の途絶を検出して縮退した。電源が戻ると自動で復帰した |

### 13.4 聴感

つまみの時定数と不感帯（8.3）、CV のスムージング（8.5、8.6）、フュージョンの切り替え（5.5）、
音声側のスムージングとミップマップの境界（`wtvco_audio_process.ja.md` §1.7、§1.10）を実際に演奏して確認し、違和感がなかったので既定値のままとした。

`firmware/wtvco/tests/` のテストは PC 上で動く（`run_tests.sh`）。入力部に関係するのは次の 3 本で、すべて合格している。
