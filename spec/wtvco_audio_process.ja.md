# WT VCO 技術仕様：オーディオ処理部

[English](wtvco_audio_process.md) | 日本語

AE Modular 用 Wavetable VCO モジュール「WT VCO」（RP2350-Zero、**1ch**）の **オーディオ処理部** の設計と、その理由、検証結果をまとめる。

- **入力部との取り決め（共有変数・コア分担・ピン）は `wtvco_input_spec.ja.md`（CV・つまみ入力部）に書く**。
- レイテンシ収支（§1.11）は、ADS1115（TI SBAS444B）・PCM5102A（TI SLAS859C）のデータシートの値にもとづく。
- 回路図と部品表は `../hardware/`、ファームウェアは `../firmware/` にある。

---

## 1.1 範囲

### 本書で扱うもの
- RP2350（RP2350-Zero）上で動作する **1ch** Wavetable オシレーター
- I2S による PCM5102A への音声出力（**自前の PIO プログラム＋DMA リング**。§1.11）と、その後ろの出力バッファ（§1.3）
- 入力部（core1）が書く**共有変数**を読んで、音程・波形位置を決める処理
- 波形テーブル / exp2 LUT のオフライン生成スクリプト

### 本書で扱わないもの
- 入力部（粗 ADC＋DMA、ADS1115、センサーフュージョン、PIC 受信、つまみ・WT CV・FM CV の変換、校正）と PIC ファームウェア
  → `wtvco_input_spec.ja.md`

### 持たない機能
- エンベロープ、フィルタなど、オシレーター以外の機能
- ミップマップ境界のクロスフェード（段差は超音波域なので対策しない。§1.7）

## 1.2 開発環境

| 項目 | 値 |
|---|---|
| IDE | Arduino IDE / Arduino CLI |
| ボードパッケージ | **arduino-pico (Earle Philhower) 6.1.0** ※Arduino公式 Mbed 版ではない |
| ボード | **RP2350-Zero**（Waveshare。FQBN `rp2040:rp2040:waveshare_rp2350_zero`） |
| I2S 出力 | **自前の PIO プログラム＋DMA リング**（arduino-pico の `I2S` ライブラリは使わない。§1.11） |
| MCU | RP2350（Cortex-M33 ×2、**単精度 FPU あり**、既定 150 MHz、SRAM 520 KB） |
| DAC | PCM5102A（SCK 不要、BCK から内蔵 PLL でシステムクロックを生成） |

### 数値表現の方針

RP2350 は単精度 FPU を持ち、入力部からの共有変数も `float` で来る（`wtvco_input_spec.ja.md` 10.2）。
そこで次のように使い分ける。

| 処理 | 表現 | 理由 |
|---|---|---|
| コントロールレート処理（共有変数の読み込み、合成、スムージング、つまみ側 pitch 算出） | **float** | 入力が float。コントロール周期あたり数十回の演算なのでコストは無視できる |
| V/OCT の読み込み（サンプルごと） | float → Q16.16 の変換 **1 回だけ** | `voct_cent × (65536/1200)` の乗算と整数変換。FPU で数サイクル（§1.5） |
| pitch → phase_inc | **Q16.16 ＋ exp2 LUT**（固定小数点） | `exp2f()` より速く、誤差も LUT のほうが小さい |
| オーディオパス（位相、テーブル参照、補間、出力ゲイン） | **固定小数点（整数）** | 位相アキュムレータは整数が本質 |

**サンプルごとのループ内では、V/OCT の変換 1 回を除いて float を使わない。**

## 1.3 オーディオ仕様

| 項目 | 値 | 備考 |
|---|---|---|
| サンプリングレート | **96 kHz** | エイリアシング対策に余裕を持たせるため |
| I2S ビット深度 | **32 bit** | |
| 音声チャンネル | **1ch**（OUT1） | |
| I2S フレーム | 32 bit × 2（L / R） | PCM5102A の I2S は常にステレオのフレーム。**L に OUT1 を出す。R は使わないが、同じ値を書く**（下記） |
| コントロール周期 | **16 サンプル**（≈167 µs、6 kHz） | つまみ・WT の更新周期。**V/OCT はサンプルごと**（§1.5） |
| 出力方式 | **DMA リング 64 フレーム、書き込みリード 8 フレーム（≈83 µs）** | 出力バッファの遅延を最小にするため（§1.11） |
| 出力レベル | **−3.4 dBFS**（Q15 で 22154） | 正弦波（フレーム 0）が PCM5102A の出力で 3 Vpp（±1.5 V、GND 中心）。ピークの大きいフレームは最大 約 3.56 Vpp。出力バッファで 2.5 V 中心にして OUT1 に出す（正弦波で 1〜4 V、最大 約 0.72〜4.28 V）。下記参照 |
| PCM5102A 補間フィルタ | **Low latency（FLT = High）** | 群遅延 3.5 tS = 36.5 µs。§1.11 |

### L / R の扱い

- OUT1 は PCM5102A の **OUTL**（6 番ピン）を出力バッファ（下記）に通して出す。
- **OUTR（7 番ピン）は使わない。どこにもつながず、オープンのままにする。GND にはつながない。**
  - OUTR は入力ではなくラインドライバの出力で、GND 中心の信号を出す。GND に落とすと出力の短絡になる
    （負荷抵抗の下限は 1 kΩ。データシート 8.3）。
  - データシートに、使わない出力チャンネルの処理についての記述はない。出力ピンなので、無負荷で開放しておけばよい。
  - 出力バッファは OUT1 の 1 回路だけ。モニターが必要なら OUT1 を分岐する。
- R にも L と同じ値を書く。コストはほぼゼロで、OUTR のピンをそのままテストポイントとして使える。
- PCM5102A のゼロデータ検出は **L / R の両方が 0** のときだけ働く（データシート 9.3.2.3）。
  R に同じ値を書いても、通常の発音中にアナログミュートへ入ることはない。

### 出力レベル

PCM5102A のフルスケール出力はデータシート公称 2.1 Vrms（正弦波で約 5.94 Vpp）。
実測では **−3 dBFS で約 4 Vpp（フルスケール換算 約 5.65 Vpp）** だったので、この実測値を基準にし、
**正弦波（フレーム 0）が PCM5102A の出力の時点で 3 Vpp（±1.5 V、GND 中心）になるようにする**。出力バッファ（下記）はゲイン −1 で、振幅は変えずに
DC レベルだけを 2.5 V に移す。OUT1 は正弦波で **1〜4 V（2.5 V 中心、3 Vpp）** になる。

**基準を「フルスケール」ではなく「正弦波」にする理由**：波形テーブルは全フレーム共通の係数で正規化している（§1.7）ので、
フレームごとにピークが違う。正弦波（フレーム 0）のピークは 25735（−2.1 dBFS）しかなく、「フルスケールで 3 Vpp」に合わせると
正弦波は 2.36 Vpp にしかならない（実測でも計算どおりだった）。そこで、聴感上の基準になる正弦波で 3 Vpp に合わせる。
ピークが最大のフレーム 15（30576）は約 3.56 Vpp（OUT1 で約 0.72〜4.28 V）になり、0〜5 V と MCP6001 の出力範囲に収まる。

```
gain = 3 / (5.65 × 25735/32768) = 0.6761  →  0.6761 × 32768 = 22154   (−3.4 dBFS)
```

別の Vpp を狙う場合（正弦波で）： `CFG_OUT_GAIN_Q15 = 32768 × 目標Vpp / (5.65 × 0.7854)`

- ゲインはオシレーターの出力（補間後）に掛け、L / R に同じ値を書く。
- 波形テーブルはフルスケール以内で生成するので、ゲイン後もクリップしない。
- 基板で PCM5102A 周りが変わる場合は、フルスケール電圧を再測定して値を見直す。
- 出力バッファのゲインは抵抗 2 本の比で決まる（1% 品で最大 ±2%）。3 Vpp を正確に合わせたい場合は OUT1 で測って値を見直す。

### 出力バッファ（ハードウェア。音声側の前提）

PCM5102A の出力は GND 中心（±1.5 V）で負に振れる。AE Modular の信号は 0〜5 V なので、
**反転増幅のバッファで 2.5 V 中心に移してから出す。**

```
                                         +---[ 100kΩ ]---+
                                         |               |
                                         +---[ 47pF ]----+
                                         |               |
OUTL --[ 470Ω ]--+--[ 10µF ]--[ 100kΩ ]--+--|-\          |
(PCM5102A)       |                          |  >---------+--[ 470Ω ]-- OUT1
             [ 2.2nF ]             +2.5V ---|+/
                 |
                GND                 MCP6001（V+ = AE 5V バス、V- = GND）
```

出力バッファは OUT1 の 1 回路だけ（OUTR は未接続）なので、**1 回路入りの MCP6001 を使う**。
V/OCT バッファ（`wtvco_input_spec.ja.md` 2.2）とは別の IC にする。電源ピン直近に 0.1 µF を置く。

| 部分 | 値 | 役割・特性 |
|---|---|---|
| 470 Ω ＋ 2.2 nF | τ ≈ 1.0 µs（fc ≈ 154 kHz） | PCM5102A の推奨出力フィルタ（データシート 8.5 の測定条件、図 33） |
| 10 µF ＋ 100 kΩ | fc ≈ 0.16 Hz（τ = 1 s） | AC 結合。GND 中心の信号から DC を切る。C0（16.35 Hz）でも減衰しない |
| 100 kΩ / 100 kΩ | ゲイン **−1**（反転） | 振幅はそのまま（正弦波で 3 Vpp）。非反転入力の +2.5 V が出力の中心になる |
| 47 pF ∥ 100 kΩ | fc ≈ 33.9 kHz（τ = 4.7 µs） | 帰還のローパス。20 kHz で約 −1.3 dB、C11（33.5 kHz）で約 −3 dB |
| MCP6001 | V+ = AE 5 V バス、RRIO、1 回路 | 出力 最大 約 0.72〜4.28 V は電源範囲に収まる。3.56 Vpp・33 kHz に必要なスルーレートは約 0.37 V/µs で、MCP6001（0.6 V/µs）の範囲内 |
| 470 Ω（出力） | — | 短絡保護と容量性負荷対策 |

- **極性が反転する。** オシレーターの用途では聴感上の影響はない。他の信号と極性を合わせる必要が出たら、
  ゲインの符号を反転する（`CFG_OUT_GAIN_Q15` を負にする）。
- **+2.5 V の基準のノイズは、可聴帯域では約 2 倍になって出力に乗る**（反転増幅のノイズゲインが 2 のため）。
  +2.5 V は十分にデカップリングする。
- 10 µF には DC 2.5 V が掛かる（オペアンプ側が正）。有極性のコンデンサを使う場合は向きに注意する。
- **電源投入直後は、10 µF が充電されるまで（τ = 1 s、数秒）OUT1 の DC レベルが 5 V 側から 2.5 V へ移っていく。**
  0〜5 V の範囲内なので害はない。
- 47 pF のローパス（τ = 4.7 µs）はレイテンシ収支に含める（§1.11）。

### I2S のピンとクロック

| GPIO | 信号 |
|---|---|
| GP14 | DAC_BCK |
| GP13 | DAC_LRCK |
| GP12 | DAC_DIN |

> **ピン**: 自前の PIO プログラムでは LRCK と BCK を side-set の連続 2 ピン
> （**side-set の基点 = GP13 = LRCK（bit 0）、GP14 = BCK（bit 1）**。BCK = LRCK + 1）、DATA を OUT ピン（GP12）にする。

> **注意**: UART0（RX = GP1）は入力部が PIC の受信に使う（`wtvco_input_spec.ja.md` 2.6）。音声側は触れない。

> **クロック**: 1 フレーム = 64 BCK（32 bit × 2）。BCK = 64 fS = **6.144 MHz**。
> これは PCM5102A の BCK PLL が内部クロックを作れる組み合わせ（データシート Table 11：96 kHz で BCK 64 fS = 6.144 MHz）。
> PIO プログラムを 1 BCK あたり 2 命令で書くと、
> 分周比は `150 MHz / (96000 × 64 × 2)` = **12.20703125 = 12 + 53/256** となり、8 bit の小数分周で**ちょうど表せる**。
> 平均サンプルレートは正確に 96000 Hz になるが、小数分周のため BCK に数 ns のジッタが乗る（PCM5102A の内蔵 PLL が吸収する範囲）。
> システムクロックは既定の 150 MHz のまま変えない。

## 1.4 外部パラメータ（入力部から受け取る値）

**入力部（core1）が書き、音声側（core0）が読む共有変数。定義は `wtvco_input_spec.ja.md` 10.2 に従う。**

| 変数 | 型 | 単位・範囲 | 入力部での更新 |
|---|---|---|---|
| `voct_cent` | float | 0〜6000 cent（入力部でクランプ済み。未接続時は 0 にならず、約 240〜360 cent になる。`wtvco_input_spec.ja.md` 6 章） | core1 ループ 1 周ごと（≤ 10 µs） |
| `coarse_cent` | float | 0〜7200 cent（C0 基準） | ヒステリシスを超えたときだけ（階段状） |
| `fine_cent` | float | −100〜+100 cent | 1 ms ごと |
| `wt_cv` | float | −0.5〜+1.5（UNI ＋ BI の合算。クランプ前） | 1 ms ごと |
| `wt_knob` | float | 0.0〜1.0 | 1 ms ごと |
| `fm_cent` | float | −6000〜+18000 cent（FM CV × DEPTH。クランプ前） | 1 ms ごと |
| `status` | uint32_t | ビットフラグ | 随時 |
| `audio_mute_req` | uint32_t | 0 / 1。core1 → core0。フラッシュ保存前のミュート要求 | 保存時のみ |
| `audio_mute_ack` | uint32_t | 0 / 1。**core0 → core1**。ミュート完了の応答 | 保存時のみ |

- 音を決める値は **6 値**（＋ `status`）。
- すべて 32 bit のアライン済み単一変数。**1 回の読み書きで完結するので排他制御は不要**。
- 入力部の既定値（PIC 途絶時・起動直後など）は入力部が責任を持つ（`wtvco_input_spec.ja.md` 8.2）。
  例：PIC なしでは `coarse_cent = 3600`（C3）、他は 0。**音声側は既定値を持たず、共有変数をそのまま使う。**
- `status` は音声側では参照しなくてよい（参照する場合もデバッグ表示程度に留め、**音を止める判断には使わない**。
  `wtvco_input_spec.ja.md` 11.2「縮退時も必ず音が出続けること」）。
- `audio_mute_req` / `audio_mute_ack` はフラッシュ保存のためのハンドシェイク（§1.12、`wtvco_input_spec.ja.md` 9.5）。
  **音を止めるのはこの要求があったときだけ。**

### 入力層の分離

**音声側は「共有変数」しか知らない。値の供給元（ADS1115 / 粗 ADC / PIC / スタブ）を一切知らない。**

- 共有変数の宣言は 1 つのヘッダ（`shared_params.h`）にまとめ、音声側と入力部の両方がそれを include する。
- 値の供給元を差し替えても、**音声側のコードは変更せずに済む**。音声側だけを固定値で試験することもできる。
- USB コンソールの試験用コマンド（`coarse`、`voct`、`ksrc stub`、`vsrc stub` など）も、この仕組みで共有変数を直接書き換える。
  使った後は `default` で入力部の値に戻す。
- 音声側は RP2350 の内蔵 ADC やつまみ用 GPIO を一切触らない（GP27 は V/OCT の粗 ADC。`wtvco_input_spec.ja.md` 2.6）。

## 1.5 内部パラメータ

### 音程の決め方

`wtvco_input_spec.ja.md` 1.3 の式に従う。

```
f = f_C0 × 2^((coarse_cent + fine_cent + voct_cent + fm_cent) / 1200)
f_C0 = 440 × 2^(−57/12) = 16.351597831 Hz   （A4 = 440 Hz、科学的音名表記）
```

内部では **C0 からのオクターブ数（対数）のまま保持し、足し算で合成する。指数変換は最後に 1 回だけ。**
つまみ側と FM はコントロール周期で、**V/OCT 側はサンプルごとに**計算する。

```
// --- コントロール周期（16 サンプルごと） ---
knob_cent = smooth_pitch(coarse_cent + fine_cent)       // §1.10。V/OCT は含めない
knob_q    = (int32_t)lrintf(knob_cent × 65536 / 1200)   // Q16.16（C0 からのオクターブ）
fm_c      = smooth_fm(fm_cent)                          // §1.10。つまみの音程とは別のスムージング
fm_q      = (int32_t)lrintf(fm_c × 65536 / 1200)        // Q16.16。負もとる
ctl_q     = knob_q + fm_q                               // コントロール周期で 1 回だけ足しておく

// --- サンプルごと ---
voct_q    = (int32_t)(voct_cent × (65536.0f / 1200))    // 共有変数を毎サンプル読む
pitch_q   = clamp(ctl_q + voct_q, PITCH_MIN_Q, PITCH_MAX_Q) // 符号付きで比較する
phase_inc = exp2_lut(pitch_q)                           // ≈10 サイクル
level     = pitch_q >> 16                               // ミップマップ段 0〜10
```

- V/OCT を毎サンプル読むことで、V/OCT の変化がコントロール周期を待たずに次のサンプルから反映される（§1.11）。
- `voct_cent` は入力部で 0〜6000 にクランプされていて 0 以上なので、整数変換の切り捨て（最大 1 LSB ≈ 0.018 cent）は問題にならない。
- ミップマップ段もサンプルごとに決まる。段の切り替えがサンプル単位で起きても問題ない。

| 項目 | 型 | 値 / 備考 |
|---|---|---|
| pitch | **Q16.16**（C0 からのオクターブ数） | 1 LSB ≈ 0.018 cent |
| PITCH_MIN | 0.0 | = C0（16.35 Hz） |
| PITCH_MAX | **11.0 − 1 LSB**（`0x000AFFFF`） | ≈ C11（33.49 kHz）の直下。下記参照 |
| 位相アキュムレータ | **uint32_t** | 96000 / 2³² ≈ 0.00002 Hz |
| WT 位置 | Q16.16 | 整数部 = フレーム番号、小数部 = クロスフェード比 |
| 中間演算 | int32_t | |

float → Q16.16 の変換精度：個々の値は最大 18000 cent 程度で、単精度の分解能は約 0.002 cent。問題ない。
加算のオーバーフロー：合計は −6100〜+31300 cent（約 −5〜+26 oct）で、Q16.16 では ±2²¹ 程度。int32_t に十分収まる。

### 音域とクランプ（`wtvco_input_spec.ja.md` 1.3）

入力の組み合わせで取りうる範囲は、FM なしで −100〜13300 cent、**FM を含めると −6100〜+31300 cent**。

| 端 | 扱い |
|---|---|
| 下端 | **C0 でクランプ**。FM なしでは COARSE = 0 で FINE を下げた場合だけ効く。FM で下向きに深く変調すると C0 に張り付く（仕様通り） |
| 上端 | **C11 直下でクランプ**（`CFG_PITCH_MAX_Q`）。FM で上向きに深く変調すると張り付く（仕様通り）。整数部を最大 10 に収めることで、ミップマップ段と exp2 LUT のシフト量が 0〜10 に収まる |

上端付近はナイキスト（48 kHz）の関係で倍音をほとんど持てず、最上段はサイン波になる（§1.7）。
可聴域を超える音をわざわざ出す必要がなければ、`CFG_PITCH_MAX_Q` を下げてよい（例：C9 = 9.0 − 1 LSB）。
**`PITCH_MAX_Q` の整数部は 10 を超えないこと**（LUT の格納倍率・テーブル段数がこれを前提にしている）。

### 周波数の基準

| pitch | 音名 | 周波数 |
|---|---|---|
| 0.0 | C0 | 16.352 Hz |
| 3.0 | C3 | 130.81 Hz |
| 6.0 | C6 | 1046.50 Hz |
| 11.0 − 1 LSB | ≈ C11 | ≈ 33488 Hz |

## 1.6 exp2 LUT

### 原理

```
phase_inc = f × 2³² / 96000
          = (f_C0 × 2³² / 96000) × 2^pitch
          = K × 2^pitch,   K = 731558.1034
```

指数法則で分解：

```
2^pitch = 2^(整数部) × 2^(小数部)
           ↑シフト      ↑テーブル参照
```

**整数部はビットシフトで済むので、テーブルは小数部（1 オクターブ分）だけでよい。**

### 仕様

| 項目 | 値 |
|---|---|
| エントリ数 | 1024 **+ 番兵 1**（計 1025、4100 byte） |
| 型 | uint32_t |
| 格納値 | `round(K × 2¹⁰ × 2^(i/1024))`, i = 0〜1024 |
| 索引 | pitch 小数部の上位 10 bit |
| 補間 | 下位 6 bit で線形補間 |
| 誤差（LUT 値、シフト前） | ≈ 0.0001 cent（試算の最悪値 0.000101 cent） |
| コスト | ≈10 サイクル |

### 格納値を 2¹⁰ 倍する理由

**最上位オクターブのシフト量ぶん（PITCH_MAX の整数部 = 10 → 2¹⁰）を先に掛けて格納**する。

- 丸め誤差が無視できるほど小さくなり、誤差は補間誤差（≈0.0001 cent）だけで決まる
- 実行時のシフトが **常に右シフト**（`10 − 整数部`）になり、分岐が消える
- 左シフトしないのでオーバーフローの心配もない

### 番兵エントリ

`LUT[i+1]` を i = 1023 でも無条件に読めるよう、**末尾に 1 エントリ追加**し
`K × 2¹⁰ × 2`（= `K × 2¹¹`）を入れる。ラップ判定が消える。
波形テーブルの「末尾に先頭サンプルを複製」と同じ考え方。

### 手順

```
1. pitch の整数部を取り出す        → 0〜10
2. 小数部の上位 10 bit で表を引く
3. 下位 6 bit で隣（番兵込み）と線形補間
4. (10 − 整数部) bit ぶん右シフト（四捨五入）
```

格納値に K を含めるので、実行時の掛け算は不要。

### オーバーフロー確認

テーブル値の最大は番兵の `K × 2¹¹` = 1,498,230,996（31 bit、< 2³¹）。
補間の差分×小数部（6 bit）も uint32_t の範囲に収まる。右シフトしかしないので範囲を出ない。
phase_inc の最大（≈ C11）も 2³¹ 未満 ＝ ナイキスト未満。

### 残る誤差

phase_inc は最終的に uint32 の整数なので、pitch 0.0（C0、phase_inc ≈ 731558）で
**±0.5 LSB ≈ 0.0012 cent** の量子化が残る。位相アキュムレータ幅で決まる下限で、LUT の精度とは無関係。
試算の全域最悪値は 0.00126 cent。

## 1.7 波形テーブル

### 3 つの軸

| 軸 | 意味 | 値 |
|---|---|---|
| ① フレーム長 | 1 周期あたりのサンプル数 | 2048（最長レベル） |
| ② フレーム数 | WT で切り替わる波形の枚数 | **16** |
| ③ ミップマップ段数 | 音程ごとの帯域制限版 | **11**（pitch 整数部 0〜10 に対応） |

### ミップマップ

高調波をそのまま高音域で鳴らすとナイキストを超えた成分が折り返す。
**オクターブごとに高調波を削った版を用意し、pitch の整数部で選択する。**
基準が C0 なので、各段の境界はすべて C の音になる。

| Level | pitch 範囲 | 音域 | 周波数 | 最大高調波 | テーブル長 |
|---|---|---|---|---|---|
| 0 | 0.0–1.0 | C0–C1 | 16.35–32.70 Hz | 1023（長さ上限） | 2048 |
| 1 | 1.0–2.0 | C1–C2 | 32.70–65.41 Hz | 733 | 2048 |
| 2 | 2.0–3.0 | C2–C3 | 65.41–130.81 Hz | 366 | 2048 |
| 3 | 3.0–4.0 | C3–C4 | 130.81–261.63 Hz | 183 | 2048 |
| 4 | 4.0–5.0 | C4–C5 | 261.63–523.25 Hz | 91 | 1024 |
| 5 | 5.0–6.0 | C5–C6 | 523.25–1046.5 Hz | 45 | 512 |
| 6 | 6.0–7.0 | C6–C7 | 1046.5–2093.0 Hz | 22 | 256 |
| 7 | 7.0–8.0 | C7–C8 | 2093.0–4186.0 Hz | 11 | 256 |
| 8 | 8.0–9.0 | C8–C9 | 4186.0–8372.0 Hz | 5 | 256 |
| 9 | 9.0–10.0 | C9–C10 | 8372.0–16744 Hz | 2 | 256 |
| 10 | 10.0–11.0 | C10–C11 | 16744–33488 Hz | 1（サイン） | 256 |

生成ルール：

```
最大高調波 = min( floor(48000 / レベル上限周波数), 最大テーブル長/2 − 1 )     上限周波数 = f_C0 × 2^(Level+1)
テーブル長 = 8 × 最大高調波 以上の最小の 2 の冪（min 256, max 2048）
```

- Level 10 は基音しか持てないので、**全フレームが同じサイン波**になる（WT を動かしても音色は変わらない。仕様通り）。
- Level 9 以上は可聴域の上端〜超音波。
- **Level 0 の最大高調波は 1023**（= 2048/2 − 1）。2048 サンプルのテーブルで 1024 次はナイキスト点にあたり、sin 成分を表せないので含めない。

### テーブル長を「8 × 最大高調波」以上にする理由

テーブルは線形補間で読む（§1.8）。線形補間は、テーブルの長さ N に対して高調波 h の**イメージ成分を (N − h) 次などに作る**。
N が 2 × 最大高調波ぎりぎりだと、最上位の高調波のイメージが約 −14 dB しか減衰せず、ナイキストを超えて可聴域に折り返す
（基音と整数比にならない濁りになる）。

帯域制限したノコギリ波での試算（96 kHz、最大のスプリアス）：

| Level | 基音 | N = 2 × 最大高調波 以上（min 32）の場合 | N = 8 × 最大高調波 以上（min 256）の場合 |
|---|---|---|---|
| 3 | 255 Hz | N = 512：−59 dBc | N = 2048：−86 dBc |
| 4 | 515 Hz | N = 256：−53 dBc | N = 1024：−83 dBc |
| 5 | 1030 Hz | N = 128：−47 dBc | N = 512：−77 dBc |
| 6 | 2050 Hz | N = 64：−42 dBc | N = 256：−68 dBc |
| 7 | 4100 Hz | N = 32：−36 dBc（9.9 kHz） | N = 256：−75 dBc |

- 8 倍以上にすると、スプリアスは全段で約 −68 dBc 以下になる。最上位の高調波の減衰（補間による高域落ち）も約 −4 dB から −0.6 dB 以内に減る。
- Level 0〜2 は長さの上限（2048）に当たって 8 倍に届かないが、その段の最上位の高調波はもともと小さく
  （ノコギリ波で −51 dB 以下）、イメージも主に超音波域に出るので問題にならない。

### メモリ

```
1 フレームあたり：2048×4 + 1024 + 512 + 256×5 = 11008 サンプル
（各テーブル +1 サンプルの複製込みで 11019 サンプル）
11019 × 2 byte = 22,038 byte/frame
22,038 × 16 frames ≈ 353 KB
```

**起動時に Flash（RP2350-Zero は 4 MB）から RAM にコピーして使う**（`CFG_TABLES_IN_RAM = 1`。exp2 LUT も同じ）。
RAM 520 KB には載る量（1 音を鳴らしている間に読むのは 2 フレーム × 1 段ぶん、最大 約 8 KB）。

- **RAM に置く理由**：Flash（XIP）に置くと、core0 のテーブル読み出しと core1 の Flash 上のコードが XIP キャッシュを奪い合う。
  その結果、core1 のループが 60〜100 µs 止まり、core0 のアンダーランも増えた。RAM に置くと、core0 の 20 µs を超える停止が 446 回から 47 回に減り、
  使用率も 12〜14% から約 10.5% に下がった。
- 同じ理由で、core0 のリング追従ループとコントロール周期の処理、core1 の粗 ADC の処理・フュージョン・入力ループは RAM 上で実行する（`RAM_FUNC`）。
  RAM 上の関数からは Flash 上のライブラリ関数を呼ばないようにする（例：`lrintf` の代わりに四捨五入をインラインで計算する）。
- `CFG_TABLES_IN_RAM = 0` にすれば Flash に置いたまま動く（性能は上記のとおり落ちる）。

### 格納形式

- 型：`int16_t`
- 各テーブルは **長さ +1 サンプル**で格納し、末尾に先頭サンプルを複製
  （補間時の `i+1` でラップ処理を省くため）
- DC 成分はゼロにする
- ピークはフルスケール以内に正規化する（全フレーム・全レベル共通の係数で。レベル間で音量が変わらないように）

### レベル選択

pitch の整数部をそのままレベル index に使う。**オクターブ境界での段の切り替えに対策はしない。**

- 段が切り替わる瞬間に変わるのは、**24〜48 kHz の超音波域の倍音だけ**である。
  境界の直前（Level L の上端）は倍音が約 48 kHz まで、直後（Level L+1 の下端）は約 24 kHz までなので、
  切り替えで消えるのはその間の成分になる（96 kHz で動かし、各段をナイキスト 48 kHz 基準で作っているため）。
- したがって可聴域の音色は変わらず、FM で境界を往復しても段差は聞こえない見込み。
- 後段の非線形（ドライブを掛けた VCF など）による相互変調や、切り替え時のクリックで聞こえる可能性はゼロではない。
  実機で FM により境界を往復させても、段差は聞こえなかった（§1.13）。

## 1.8 補間

1 サンプルあたり **テーブル参照 4 回**。

```
idx       = phase >> (32 - LOG2_LEN)
phaseFrac = (phase << LOG2_LEN) >> 24        // 8 bit

a = lerp(tbl[f  ][idx], tbl[f  ][idx+1], phaseFrac)
b = lerp(tbl[f+1][idx], tbl[f+1][idx+1], phaseFrac)
s = lerp(a, b, frameFrac)                     // 8 bit
```

WT → フレーム位置：`wtPos = WT × 15`（16 フレーム = 15 区間）。
`WT = 1.0` のとき `f = 15`、`f+1` は範囲外になるので、**`f = 14`、frameFrac = 最大** に丸めるか、
`wtPos` を `15.0 − 1 LSB` でクランプする。

## 1.9 WT 位置の合成（`wtvco_input_spec.ja.md` 10.3）

```
wt = clamp(wt_knob + wt_cv, 0.0, 1.0)
```

- **KNOB を基準位置、CV をそこからの変調量として足す。**
- `wt_cv` は、入力部がユニポーラ入力（UNI）とバイポーラ入力（BI）を合算した値で、範囲は **−0.5〜+1.5**（`wtvco_input_spec.ja.md` 2.5・8.4・8.5）。

  | 入力 | 受ける電圧 | 変調量 |
  |---|---|---|
  | UNI | 0〜5 V（0 V 基準） | 0〜+1.0（上向きだけ） |
  | BI | 0〜5 V（2.5 V 中心） | −0.5〜+0.5（上下両方） |

  感度は両入力とも 1 V = 0.2。
- **クランプはここで 1 回だけ行う。** 入力部はクランプせずに渡すので、合計がはみ出た分はここで 0.0 / 1.0 に張り付く。
- CV 未接続時は `wt_cv = 0`（UNI はプルダウンで 0 V、BI はバイアスで 2.5 V。入力部の仕様）なので、KNOB の位置だけで決まる。
- AE Modular の LFO（0〜5 V、2.5 V 中心）を BI に入れると、KNOB の位置を中心に ±0.5 振れる。KNOB を中央にすれば全域（0〜1）を往復する。
- ADSR など 0 V 基準の CV は UNI に入れる。両挿しすれば ADSR＋LFO のような複合変調になる。
- 合成はコントロール周期で行い、スムージング（§1.10）の後に Q16.16 の WT 位置へ変換する。

## 1.10 パラメータスムージング

入力部でもスムージングはされているが、共有変数は 1 ms ごと、あるいはヒステリシス越えのときだけ
**階段状に**変わる（`wtvco_input_spec.ja.md` 10.3）。そのまま使うとジッパーノイズが出るので、
音声側でコントロールレート（6 kHz）の 1 次ローパスを掛ける。

| パラメータ | 時定数（初期値） | 備考 |
|---|---|---|
| `coarse_cent + fine_cent`（つまみの音程） | **5 ms** | COARSE はヒステリシス越えで 4〜5 cent 以上の段差で来る。これを滑らかにつなぐ |
| `voct_cent` | **掛けない** | 下記参照 |
| WT（`wt_knob + wt_cv` の合成後） | **2 ms** | 1 ms の階段を消す程度。WT CV の中速変調を鈍らせない |
| `fm_cent` | **2 ms** | つまみの音程とは別に掛ける。5 ms（fc ≈ 32 Hz）では速めの LFO が鈍るため |

時定数は `config.h` にある。実際に演奏して違和感がなかったので、上の初期値のまま決めた（§1.13）。
USB コンソールの `tune` コマンドで、書き込みなしに（RAM 上だけで）値を変えて試せる。

### V/OCT にスムージングを掛けない理由

- V/OCT には**ノートオンから 500 µs 以内の追従**という要求がある（`wtvco_input_spec.ja.md` 1.4）。
  2 ms の 1 次ローパスを掛けると、それだけで 63% 到達に 2 ms かかり要求を満たせない。
- モード遷移時の段差（FAST ↔ ADS）の補間は、入力部が `SMOOTH_MS` で行っている（`wtvco_input_spec.ja.md` 5.5）。
- したがって音声側は **`voct_cent` を毎サンプルそのまま読んで使う**（§1.5）。

## 1.11 レイテンシと I2S 出力

### V/OCT の要求

ノートオンから音声出力までを **500 µs 以内**（`wtvco_input_spec.ja.md` 1.4）。
入力部の消費は最悪 約 52 µs、典型 約 42 µs（`wtvco_input_spec.ja.md` 10.4）。

### 削減策の全体像

| 案 | 内容 | 担当 | 効果（最悪値） |
|---|---|---|---|
| A | V/OCT をサンプルごとに読む（§1.5） | 音声側 | コントロール周期の待ち 167 µs → 1 フレーム（10.4 µs） |
| B | I2S 出力を自前の PIO＋DMA リングにし、読み出し位置の N フレーム先を追いかけて書く（下記） | 音声側 | 出力の待ち行列を N ＋ FIFO 2 フレーム（N = 8 で約 104 µs）に限定 |
| C | ADS1115 の I2C 読み出しをノンブロッキングにする | 入力部 | core1 の処理遅れ 約 70 µs → 10 µs 以下（`wtvco_input_spec.ja.md` 4.4） |
| D | 急変判定を生サンプルごとの移動平均で行う | 入力部 | 粗サンプルの区切り待ち＋確定 約 100 µs → 約 40 µs（`wtvco_input_spec.ja.md` 5.3） |

### I2S 出力：PIO＋DMA リング（案 B）

arduino-pico の `I2S` ライブラリはバッファのキューを持ち、定常状態ではキューが常に満杯になるため、
キュー全体の長さ（数百 µs）がそのまま遅延になる。これを使わず、**DMA がループで読み続けるリングに、
core0 が「DMA の読み出し位置の N フレーム先」まで書き足していく**方式にする。
入力部の粗 ADC（DMA リングを core1 が追いかける）と同じ構造を、出力向きに使う。

```
          core0 が書く（読み出し位置の N フレーム先まで）
                ↓
  [ リング 64 フレーム（512 byte、512 byte 境界に配置） ] ──DMA（無限ループ）──→ PIO TX FIFO ──→ I2S（GP12/13/14）
                ↑
          DMA の読み出し位置（READ_ADDR から求める）
```

| 項目 | 値 | 備考 |
|---|---|---|
| リング長 | **64 フレーム**（1 フレーム = L/R 各 32 bit = 8 byte、計 512 byte） | `CFG_OUT_RING_FRAMES`。2 のべき乗。**リング長と同じバイト境界に配置**（DMA のリングラップのため） |
| 書き込みリード N | **8 フレーム（≈83 µs）** | `CFG_OUT_LEAD_FRAMES`。実測で決めた（下記）。上限 31 フレーム |
| DMA | 読み出し側をリングラップ（2⁹ byte）、PIO の TX DREQ でペーシング、**止まらずに回り続ける** | RP2350 の DMA の転送カウントの無限（ENDLESS）モードを使う（arduino-pico 6.1.0 同梱の pico-sdk の `dma_encode_endless_transfer_count()`） |
| PIO TX FIFO | **結合しない**（4 ワード = 2 フレーム） | FIFO も遅延になるので深くしない |

**core0 のループ（擬似コード）**

```c
for (;;) {
    rd   = dma_read_frame_index();                 // (READ_ADDR - ring_base) / 8
    lead = (wr - rd) & (RING - 1);
    if (lead > RING / 2) {                         // 書き込みが読み出しに追い越された = アンダーラン
        underrun_cnt++;
        wr = (rd + LEAD) & (RING - 1);             // 位置を合わせ直す（古いフレームが一瞬鳴る）
        continue;
    }
    min_lead = min(min_lead, lead);                // 余裕の監視（下記）
    while (((wr - rd) & (RING - 1)) < LEAD) {
        if (++ctl_cnt == CTRL_PERIOD) { control_update(); ctl_cnt = 0; }  // コントロール周期
        render_frame(&ring[wr]);                   // 1 サンプル生成 → ゲイン → L/R に同じ値を書き込み
        wr = (wr + 1) & (RING - 1);
    }
}
```

- core0 はこのループ専用とし、他の処理を入れない（ビジーウェイトでよい）。
- 起動時はリングを 0 で埋めてから DMA と PIO を開始し、`wr = rd + N` から書き始める。
- **`min_lead`（観測した最小のリード）を記録する。** これが 0 に近づくほどアンダーランに近い。
  USB コンソールの `show` コマンドで `underrun_cnt` と一緒に見られる。
- アンダーラン判定 `lead > RING / 2` が成り立つには、通常時のリードが常に RING / 2 = 32 フレーム以下である必要がある。
  **N は 31 以下**とする（下記「収支」の上限とも一致する）。

**N の決め方**

- N は「core0 が割り込みなどで止められる最大時間」より大きくなければならない。
- arduino-pico では USB（TinyUSB）の処理（core0 で 1 ms ごとの `tud_task()` と USB 割り込み）が core0 に入る。
- 実測では、USB 未接続（演奏時）の core0 の最長停止は 37 µs で、**N = 8（83 µs）でアンダーランは 0 回**だった（§1.13）。
  USB 接続中は最大 131 µs 止まり、接続やポートの開閉のときなどにまれにアンダーランが出る。
  USB を使うのは校正などのときだけなので、これは許容し、N = 8 に決めた。
- 足りない場合は N を増やす（N = 16 で 167 µs。上限は下記「収支」の 31 フレーム）。
- 入力部の割り込み（RDY の GPIO 割り込み、DMA など）は core1 で登録し、core0 に来ないようにする（`wtvco_input_spec.ja.md` 10.1）。

### PCM5102A の遅延と設定（データシート SLAS859C より）

PCM5102A の補間フィルタは **FLT ピン（11 番）を High にして Low latency（IIR）フィルタを使う**（データシート 9.3.4.1、Table 3）。

| 項目 | Low latency（FLT = High、採用） | Normal（FLT = Low） | 出典 |
|---|---|---|---|
| 群遅延 | **3.5 tS = 36.5 µs**（96 kHz） | 20〜22 tS = 208〜229 µs | 電気的特性表、Table 4・7・8 |
| 通過域 | 0.47 fS（45.1 kHz） | 0.45 fS（43.2 kHz） | 電気的特性表 |
| 通過域リップル | ±0.0001 dB | ±0.02 dB | Table 4・7 |
| 阻止域 / 減衰 | 0.55 fS（52.8 kHz）以上 / −52 dB | 0.55 fS 以上 / −60 dB | Table 4・7 |

- 1 tS = 1/fS = 10.42 µs（96 kHz）。
- 96 kHz は PCM5102A の内部で「ダブルレート」として検出され、補間段数は x8 ではなく x4 系になるが、
  Low latency の群遅延は x8・x4 とも 3.5 tS で同じ（Table 7・8）。
- Normal フィルタでは群遅延だけで最大 229 µs となり、収支を大きく圧迫する。**FLT = High は必須。**
- 阻止域は 52.8 kHz 以上なので、減衰量の違いが効くのは**超音波域のイメージ成分だけ**で、可聴帯域には影響しない。
- IIR なので位相は直線でない（群遅延が周波数で変わる）。高域の倍音の位相がわずかにずれ、波形の見た目は変わりうるが、
  オシレーターの用途では聴感上の問題はない。
- 推奨出力フィルタ（470 Ω ＋ 2.2 nF、データシート 8.5 の測定条件）の時定数は約 1.0 µs で、無視できる。
- その後ろの出力バッファ（§1.3）は、帰還の 100 kΩ ∥ 47 pF で時定数 4.7 µs のローパスになる。収支に含める。
- ΔΣ変調器・チャージポンプ出力段の遅延はデータシートに記載がなく、上記フィルタ遅延に比べて十分小さいとみなす。

### 収支（V/OCT：ノートオン → 音声出力）

| 要素 | 最悪 | 典型 | 根拠 |
|---|---|---|---|
| 入力部（ノートオン → 共有変数） | 52 µs | 42 µs | `wtvco_input_spec.ja.md` 10.4（案 C・D 込み） |
| 共有変数を読むまでの待ち | 10.4 µs | 5.2 µs | 案 A。core0 は 1 フレーム（1/96 kHz）ごとに 1 サンプル生成し、そのたびに読む |
| 出力リング（リード N） | 83.3 µs | 83.3 µs | 案 B。N = 8 フレーム × 10.42 µs |
| PIO TX FIFO | 20.8 µs | 20.8 µs | 結合なし 4 ワード = 2 フレーム |
| I2S 送出（1 フレーム） | 10.4 µs | 10.4 µs | 64 BCK ÷ 6.144 MHz |
| PCM5102A 補間フィルタ | 36.5 µs | 36.5 µs | 3.5 tS（FLT = High） |
| 出力 RC フィルタ | 1.0 µs | 1.0 µs | 470 Ω × 2.2 nF |
| 出力バッファ | 4.7 µs | 4.7 µs | 100 kΩ × 47 pF（§1.3） |
| **合計** | **約 219 µs** | **約 204 µs** | **500 µs 以内。余裕は最悪で約 281 µs** |

- 音声側だけの合計は **最悪 約 167 µs、典型 約 162 µs**（上表の 2 行目以降。OUT1 まで）。
- 入力部の値は、半音以上の音程変化の場合。それより小さな変化は急変の判定に少し長くかかる（`wtvco_input_spec.ja.md` 10.4）。
- N 以外の要素の合計は最悪 約 136 µs。N を 16 にしても合計は約 303 µs で、500 µs に収まる。
- **N の上限は 31 フレーム**（合計 約 459 µs。ばらつきを見込んで約 40 µs を残す。リングのアンダーラン判定の条件 N ≤ 31 とも一致）。
  これを超える N が必要になった場合は、core0 を止めている割り込みの対策を先に行う。

### ハードウェアへの要求（PCM5102A のピン設定）

| ピン | 設定 | 理由（データシート） |
|---|---|---|
| FLT（11） | **High（3.3 V）** | Low latency フィルタ（9.3.4.1） |
| FMT（16） | Low | I2S フォーマット（9.3.2.2） |
| DEMP（10） | Low | デエンファシス無効 |
| XSMT（17） | High（AVDD へ直結、または外部制御） | ソフトミュート解除（9.3.3） |
| SCK（12） | **GND** | SCK が 16 LRCK 以上 Low のとき、BCK から内蔵 PLL でクロックを作る（9.3.5.3） |

市販の PCM5102A モジュールは FLT・FMT・DEMP・XSMT をはんだジャンパで設定しているものが多いので、
**使うモジュールで FLT が High になっていることを確認する**。

### PCM5102A のその他の挙動（レイテンシ以外の注意）

- **ゼロデータ検出**：L/R とも 0 が 1024 LRCK（96 kHz で約 10.7 ms）続くとアナログミュートに入る（データシート 9.3.2.3）。
  オシレーターは常に音を出しているので通常は起きないが、フラッシュ保存時のミュート（§1.12）では入る。
  ミュートを解除すると、音は正常に戻る。
- **クロック異常**：LRCK と BCK の関係が 4 LRCK 以上崩れると、出力をバイポーラゼロにして再同期する（データシート 9.3.2.1）。
  PIO と DMA は止めずに回し続けるので、通常は起きない。
- **起動**：I2S クロックが来てから内部リセット解除まで約 4 ms かかる（データシート 図 41）。起動直後の無音はこのため。

### WT CV・つまみ

入力部で最悪 約 1.6 ms（PIC のフレーム周期＋変換＋送信。`wtvco_input_spec.ja.md` 10.4）＋入力部のスムージング。
音声側はコントロール周期（≤ 167 µs）＋出力（約 167 µs）＋ 2〜5 ms のスムージング。中速要求には十分。

## 1.12 コア分担と CPU / メモリ見積もり

### コア分担（`wtvco_input_spec.ja.md` 10.1）

| コア | 役割 | arduino-pico での入口 |
|---|---|---|
| **core0** | **音声合成、出力リングへの書き込み**（このループ専用） | `setup()` / `loop()` |
| **core1** | 入力処理（`input.*`）、USB コンソール（`console.*`） | `setup1()` / `loop1()` |

> **注意**: arduino-pico では USB（TinyUSB）の処理が core0 に入る。USB コンソールのコマンドは core1 のループで処理するが、
> USB の処理自体が core0 を止めるので、USB 接続中はまれにアンダーランが出る（§1.11、§1.13）。

### フラッシュ保存時のミュート（ハンドシェイク）

校正値のフラッシュ保存中は XIP が止まり、両コアが待たされる（`wtvco_input_spec.ja.md` 9.5）。
このとき**DMA と PIO は SRAM のリングを読み続ける**ので、何もしないとリングに残った 64 フレームが
繰り返し再生され、**1.5 kHz（96 kHz / 64）のブザー音**になる。これを避けるため、保存の前にリングを無音にする。

```
core1（保存コマンド受信）           core0（音声）
  audio_mute_req = 1  ─────────→  フェードアウト（約 2 ms）
                                    リング全体（64 フレーム以上）を 0 で書く
                      ←─────────  audio_mute_ack = 1
  フラッシュ保存（両コア停止。
   DMA はリングの 0 を出し続ける）
  audio_mute_req = 0  ─────────→  ack = 0、書き込み位置を合わせ直し、2 ms でフェードインして通常動作に戻る
```

- core1 は `audio_mute_ack` を待ってから保存する。50 ms 待っても来なければ保存を中止し、エラーを表示する。
- 解除時のフェードイン（2 ms）は、クリックを防ぐため。
- ミュート中はゼロデータ検出で PCM5102A がアナログミュートに入る（§1.11）。解除すると音は戻る。
- 保存は校正モード中だけ行う取り決めなので、この間の無音は許容する。

### CPU 見積もり

```
150 MHz ÷ 96 kHz = 1562 サイクル/サンプル
1 声ぶんの補間処理（テーブル参照 4 回＋lerp 3 回） ≈ 80 サイクル
ゲイン・L/R 書き込み ≈ 10 サイクル
V/OCT のサンプルごとの変換＋exp2 LUT ≈ 20 サイクル
コントロールレート処理（float）はコントロール周期あたり数百サイクル → 1 サンプルあたり数十サイクル
→ 使用率 約 8〜12%
```

core0 は出力リングを追いかけてビジーウェイトするので、使用率は「フレーム生成に使った時間 ÷ 経過時間」で測る。

### メモリ

- RAM 520 KB：波形テーブル ≈353 KB ＋ exp2 LUT 4 KB（§1.7。起動時に Flash からコピー）、状態変数、出力リング（512 byte）、入力部の DMA リング（16 bit × 1024）。
  合計で約 72%（§1.13）
- Flash 4 MB：プログラム、波形テーブルと exp2 LUT の初期値

### フラッシュ保存時のアンダーラン（USB 接続中のみ）

USB のポートを開いたまま、同じセッションで切り分けた。

| 操作 | アンダーラン |
|---|---|
| 待機 10 秒 | 0 回 |
| ミュートのハンドシェイクだけ（`mute 100`） | 0 回 |
| `calsave`（フラッシュ書き込み 31 ms） | 2 回 |

ミュート中は音を出していないので、書き込み中に止められていた USB の処理が、解放の直後に core0 でまとめて走るためと考えられる（加えて XIP キャッシュが空になる）。
保存は USB のコンソールからしかできないので、演奏時（USB なし）には起きない。解放直後はフェードイン中で振幅も小さいので、対策はしていない。

### 聴感
